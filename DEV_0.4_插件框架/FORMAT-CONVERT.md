# SolidWorks 批量转换为天工格式（DEV 0.5）

把 SolidWorks 的装配（.SLDASM）、零件（.SLDPRT）、工程图（.SLDDRW）批量转换成天工 CAD 的原生
格式（.asm / .par / .psm / .dft），转换结果自动落盘，下次直接打开天工文件，不需要再转换一遍。

- 独立程序：`TianGongConverter.exe`（不需要天工 CAD 已启动，双击即可用）
- 插件命令：天工 CAD 功能区「插件（加载项）→ 功能 → SolidWorks 批量转换」（命令 ID 5）

## 1. 它解决什么问题

天工 CAD 打开 SolidWorks 文件是在**内存里**完成转换的：

- 转换出来的文档 `FullName` 只有名字、没有磁盘路径，也就是「未保存」状态；
- 不点保存，退出后结果就丢了，下次还要从头再转一遍；
- 一个装配里每个零件（.par）都是独立文档，要逐个保存；
- 一次只能盯一个文件，多个装配体要反复手工操作。

本工具对每个 SolidWorks 文件调用天工 CAD 自带的转换器打开，然后把转换出来的**全部文档**
（顶层装配 + 所有子装配 + 所有零件）写到指定目录，再关闭。

## 2. 算法与复杂度

```text
扫描输入            O(文件数)            每个目录只遍历一次
任务划分            O(n log n)           按输入目录分组后 LPT 配平
每个文件：
  打开并转换        O(1) 次 COM 调用     耗时 = 天工 CAD 转换 Parasolid 的时间（瓶颈）
  遍历文档树        O(文档数)            按 FullName+Type 去重
  保存              O(文档数) 次 SaveAs  后序遍历：先零件、后装配
  关闭              O(文档数)
```

- 每个文件只打开一次，每个文档只保存一次；没有重复遍历，没有重复转换。
- LPT（最长处理时间优先）配平后完工时间不超过最优解的 4/3，代价只有一次排序。
- 工具自身开销只有每个文档 4~11 ms 的 SaveAs 调度。**处理时间瓶颈就是天工 CAD 转换的效率。**

## 3. 使用

### 3.1 独立程序（推荐）

1. 双击 `TianGongConverter.exe`；
2. 「添加文件夹…」选择装着 SolidWorks 文件的目录（可加多个），或「添加文件…」挑单个文件；
3. 选输出目录（默认在源目录旁新建 `天工格式输出`）；
4. 默认勾选：镜像源目录结构、包含零件、包含装配、包含子文件夹；
5. 点「开始转换」。结束后写出 `转换报告-<时间>.csv`，每行一个文件的状态与耗时。

不用管天工 CAD 是否已经打开：工具会自己拉起**隐藏的** CAD 进程，不占用你正在用的窗口。

### 3.2 插件方式

运行 `安装.cmd` 后重启天工 CAD，功能区「插件（加载项）→ 功能」出现
「SolidWorks 批量转换」，以当前装配所在目录作为默认输入。

## 4. 输出目录结构

默认「镜像源目录结构」：

```text
输出目录\
  项目A\                 <- 对应源目录 项目A\
    Part1.par
    组件.asm
    总装.asm
    总装.cfg
```

装配引用零件的路径会在保存时**自动指向输出位置**，所以输出目录可以整体拷走，直接打开
`.asm` 就能用。实测：重新打开转换后的装配，6 个顶层引用全部命中新目录，FileMissing=False。

- 取消「镜像源目录结构」= 结果平铺在一个目录（同名会覆盖）。
- 「覆盖已存在的转换结果」默认关闭：**输出已存在就跳过**，所以中断后重跑只补没做完的。
- 「转换后重新打开校验引用」：转换完再打开一次输出装配，确认没丢引用，适合关键批次。

## 5. 提速手段（实测）

### 5.1 有效的

1. **结果落盘 + 跳过已转换文件**（效果最大）。原来的流程每次都要重新转换一遍；本工具转换结果
   一旦落盘，下次运行对已存在输出的文件只做一次 O(1) 的存在性判断就跳过。对「转换一次、长期
   复用」的批次，第二次开始耗时接近 0。
2. **整批复用同一个 CAD 会话**。CAD 启动一次约 13.5 秒，单独进程启动一次即可处理整批文件；
   手工方式每打开一个文件都要重新走一遍启动和加载。
3. **关掉撤销记录**（`seApplicationGlobalPartandAsmUndoSteps=0`）并关闭重绘、弹窗、启动画面，
   去掉每个文档的撤销簿记开销。
4. **省掉一次转换**：批量把整个项目的顶层装配加进来时，子装配/零件会作为文档一起转换并落盘，
   稍后轮到它们作为独立条目时会被「输出已存在」直接跳过（实测 16 个文件中有 4 个属于这种情况）。

### 5.2 试过、但**没有**明显提速的

**多开 CAD 进程并行转换**。实测数据（16 个装配，同一目录，全部成功）：

| 方式 | 总耗时 | 单件累计耗时 | 结果 |
| --- | --- | --- | --- |
| 1 个进程 | 204.4 s | 189.5 s | 12 成功 / 4 跳过 / 0 失败 |
| 4 个进程 | 165.7 s | 300.2 s | 15 成功 / 1 失败 |

只有 1.23 倍，原因是：

- 4 个 CAD 实例的启动要排队，第 4 个实例要 76.8 秒才就绪；
- 并行时单件转换时间反而变长 1.6 倍（争用同一个转换器），机器 CPU 占用始终只有 12%~15%，
  说明瓶颈不在 CPU，加进程换不来吞吐。

更严重的是并行时**个别零件会保存失败**（实测 `534779_VSVA-B-P53E-H-A2-1R2L.par` 报 DISP_E_EXCEPTION）：
即使把两个进程分到完全不同的输入目录、并且用系统级互斥体把保存动作串行化，3 次并行实测都复现了
这个问题，说明天工 CAD 的 SolidWorks 转换器不适用于「两个 CAD 进程同时转换同一批数据」。

因此**默认就是单进程**（「并行进程」默认 1，勾选「自动」也是 1）。并行只作为实验选项保留，
并且每个文件失败后会自动重试一次。除非你确认过某个批次可以稳定并行，否则请保持 1。

## 6. 实测耗时构成

8 个装配、单进程、全部成功：

| 指标 | 数值 |
| --- | --- |
| 单件累计耗时 | 108.4 s |
| 其中打开 + 转换 | 约 88%（3.9 ~ 27.2 s/文件） |
| 其中保存全部文档 | 约 12%（0.14 ~ 7.7 s/文件，文档越多越久） |
| CAD 启动（每进程一次） | 13.5 s |
| 每文档保存调度开销 | 4 ~ 11 ms |
| 整批吞吐（1 个进程） | 约 4.7 个文件/分钟 |

## 7. 安全设计

- 工作进程与它们拉起的隐藏 CAD 进程都放在一个 Windows 作业对象里，点「停止」或工具被强杀时
  会一起结束，不留僵尸进程。
- 同一个输出文件用认领锁 + 系统级命名互斥体保护，多个进程不会同时写同一个文件。
- 输出目录与源目录不要互相嵌套，避免把自己的输出再扫进来。
- 失败的文件会自动重试一次，并在 CSV 报告里记录具体错误。

## 8. 已知边界

- 转换速度取决于天工 CAD 自带的 SolidWorks 转换器，本工具不改变转换算法。
- 源装配缺引用的零件时，天工 CAD 打开就缺件，工具照常保存已有文档并在报告里记录。
- 工程图（.SLDDRW → .dft）默认不转换，需要时勾选。
- **天工 CAD 的 SolidWorks 转换器本身会把转换出来的零件文件写到源文件旁边**（转换器选项
  `Output in the same folder=On` 的行为），这跟用不用本工具无关：只要打开一次 SolidWorks 装配，
  源目录旁边就会出现一批 .par。本工具在此基础上把**完整结果（含顶层装配 .asm）**写到输出目录。
  如果不希望源目录被写入，可以在天工 CAD 的「选项 → 导入/导出 → SolidWorks」里把输出目录改成
  单独的文件夹。
- 「并行进程 >1」是实验特性：实测加速只有约 1.2 倍，且 3 次实测都出现过零件保存失败。
  生产批次请保持 1 个进程。
