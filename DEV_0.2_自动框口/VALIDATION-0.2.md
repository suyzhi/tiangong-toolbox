## 实测通过

| 内容 | 结果 |
|---|---|
| 编译 | .NET Framework x64 编译成功，无错误或警告 |
| 原生命令 | 手动命令 62016、自动命令 62017 注册成功；独立 CLSID、DLL、命名空间 |
| 原手动功能回归 | 实际装配面/定位点、普通和嵌套坐标、可编辑草图、对称拉伸、重名和发布失败清理等原测试通过 |
| 新自动几何 | 单框、双框、分离的两个框、空间旋转、缺边、2 mm 断角、部分隔断及无实际平面支撑的包围盒情况 |
| 普通装配 | 自动模式读取实际嵌套普通 PAR 型材并识别框口 |
| 原生框架样件 | StructuralFrames.Add 使用自带 20x1.5.par 方管库的独立副本生成闭合斜接框架；4 个实际型材实例均为框架覆盖实体 |
| 单框口 | 路径 520 × 320 mm，净框口 500 × 300 mm，间隙 1 mm，生成 498 × 298 × 6 mm PAR |
| 双框口 | 原生方管外框加中间立柱共 5 根型材，识别两框口，批量生成两块 238 × 298 × 6 mm PAR |
| 嵌套原生框架 | 整个框架子装配作任意空间旋转和平移后，自动读取坐标与预期一致并生成板子 |
| 重复选择 | 同一实例重复传入去重，共用同一库文件的不同实例不混淆 |
| 自动窗口 | 通过真实 CAD SelectSet 读取所选实例，单/双框口列表、参数计算与预览绘制通过；关闭预览实例数量及 Dirty 状态不变 |
| 保存重开 | 单板、双板均在实际 CAD 保存重开后核查实体尺寸；双板额外逐项检查 16 元素装配位置矩阵 |
| 批次回退 | 第二块板建模失败时，第一块已生成板子和装配引用被撤回 |
| 原文件保护 | 原 src/tests/tools 全部 SHA-256 与开发前一致；安装方管库和复制后的截面文件测试前后 SHA-256 一致 |

最终测试模型原始位置：DEV_0.2_自动框口/artifacts/cad-20260908-142817/AutoFrame。
交付 examples/AutoFrame 中包含对应模型依赖、单/双框口预览和尺寸清单。NativeStructuralFrame.asm 为单框板样件，NativeTwoOpenings.asm 为双框板样件，NestedAuto.asm 为旋转嵌套样件。

## 仍未通过完整验收的项目

- 实际用鼠标在 CAD 工具栏点击新增按钮、Ctrl 多选或框选、再通过输出文件夹对话框完成生成的整条交互链。当前测试用真实 SelectSet 和插件窗口执行，但没有用鼠标逐步完成。
- Windows computer-use 截图两次均返回 SetIsBorderRequired failed: 不支持此接口 (0x80004002)。没有绕过截图失败进行盲点操作。
- 本轮 CAD View.SaveAsImage 导出的视口图为全黑，不能作为模型视觉验收证据。仅插件 DrawToBitmap 预览图已视觉检查，模型尺寸/位置/保存重开通过原生 CAD 实体接口确认。
- 用户实际复杂铝型材、槽口自动识别、伸入槽底的嵌装意图、大型三维框架和多显示器/DPI 尚未验收。
- 当前每次处理一个共同厚度中面，立体框架应按面分组；自动模式取净框口，不推断槽底位置。
- 不检查未选中零件的干涉，不自动更新或替换旧板；输出目录迁移到其他电脑后的引用重定位尚未验证。
