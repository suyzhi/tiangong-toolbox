## B. 配孔检查（命令 8，提交 `ce814ae`）

修了三个问题：
- **漏打孔一条都报不出来。** 窗口建零件表时，所有零件都被当成"已存在"跳过，实体全是空的。
- **漏打孔的射线坐标系错了。** 原来直接用装配坐标打零件自己坐标系里的几何，零件只要不在原点就打偏。
- **孔偏了几乎不触发。** 原来分组容差和判偏容差都是 0.2mm，偏 0.5mm 的一对孔会被拆成两个默认隐藏的"孤孔"。
  现在两孔相距不超过较小孔的半径就算同一组，组内再按 0.2mm 判偏。

**使用上的变化**：以前从来没出现过的"漏打孔""孔偏了"，现在会报出来，这是预期的。

准备两个零件（新建或用 LiveA / LiveB 夹具的**副本**）：

- **板 A**：100×50×10mm，打一个 **Φ5 通孔**（M6 螺纹底孔）。
- **板 B**：同尺寸，打一个 **Φ6.6 通孔**（M6 过孔）；再准备一个**实心**的板 C（不打孔）。

### B1 基准：对齐的一对孔不报问题

装配：A 在下，B 叠在 A 上方，两孔同轴对齐。运行命令 8 →「开始检查」。

- [ ] 期望：没有问题（"没有发现问题"）。这一步用来确认改动没有带来误报。

### B2 孔偏了（重点）

把 B 在装配里沿板面**平移 0.5mm**，其它不动，重新检查。

- [ ] 期望：报 1 条 **孔偏了**，"同组孔最大偏心 0.5mm（容差 0.2mm）"。以前这里什么都不报。
- 再把 B 平移到偏 **1mm**，期望同样报孔偏了，偏心 1mm。
- 平移到偏 **3mm**（超过 Φ5 的半径 2.5mm）：不再算同一组，不报孔偏了，改报 **1 条漏打孔**，挂在 **B 的孔**上：
  B 的孔轴线落在了 A 的实体上；而 A 的孔轴线还在 B 的 Φ6.6 孔里面，碰不到实体。这是新口径下的预期结果。

### B3 漏打孔 + 零件转过角度（重点）

装配：A + 实心板 C。把 C 放到 A 的孔正上方盖住它，并且让 C **绕 Z 轴转 90°、再平移到别的位置**，只要还盖住 A 的孔就行（关键是 C 不在装配原点、也不是原始朝向）。

- [ ] 期望：报 1 条 **漏打孔**："A… 上的 Φ5 孔（@X… Y… Z…）轴线穿过了其他零件，但对方没有对应的孔"。以前这里一条都不报。
- 把 C 挪开，不再盖住 A 的孔，重新检查：期望**不报**漏打孔（勾不勾"忽略孤孔"都一样）。
- 可选：C 绕 X 轴转 90° 立起来，挡在 A 的孔轴线上，期望同样报漏打孔（这一步验证轴线**方向**的换算）。

### B4 同一个零件用了两次

在 B3 的装配里再插入一个 C（同一个 .par 文件的第二个实例）。先让**第一个** C 挡住 A 的孔、第二个放远处；
再反过来，让**第二个** C 挡住、第一个放远处。每次都重新检查。

- [ ] 期望：两种摆法都是**恰好 1 条**漏打孔（挂在 A 的孔上）。每个实例用自己的位置判断，不会因为同名 / 同文件而错判或漏判。

### B5 回归

- [ ] 装配里有圆柱沉孔 + 对方螺纹底孔的正确组合：不报"配错孔"（沉孔的两条圆边不能被当成两个孔）。
- [ ] 命令 6「自动打孔」、命令 7「批量排孔」各走一遍：这两个命令的打孔代码这次没改，只确认没有被连带影响。

## C. 批量格式转换（命令 5，提交 `8bba173`）

需要几份 SolidWorks 或 STEP 源文件（复制一份做实验）。

### C1 输出目录是盘符根目录（重点）

以前拼 worker 参数时，`D:\` 会变成 `"D:\"`，其中 `\"` 被当成字面引号，后面的参数全部错位。
不想弄脏真盘符，就用 `subst` 造一个虚拟盘：

```powershell
New-Item -ItemType Directory -Force C:\temp\tg-out | Out-Null
subst X: C:\temp\tg-out
```

1. 命令 5 → 输出目录选 `X:\` → 开始转换。
   - [ ] 期望：正常转换，结果落在 `X:\`（也就是 `C:\temp\tg-out`）下。以前会失败，或者输出路径错乱。
2. 独立版的 `--input` 参数也有同样的问题：把一个装配文件放在 `X:\` 根目录、在 CAD 里打开它，再点命令 5。
   - [ ] 期望：转换窗口的"输入"预填为 `X:\`。
3. 清理：`subst X: /d`。

### C2 断点续做不再跳过没转完的装配（重点）

新机制：每个文件开始转换前，在输出位置写一个 `<源文件名>.tgconvert-pending` 标记（例如 `总装.SLDASM.tgconvert-pending`），
成功后才删掉。下次续做时，只要标记还在，就算顶层文件已经存在，也会重新转换。

1. 正常转换一个文件夹（至少两个装配），**不勾「覆盖已存在的转换结果」**。
   - [ ] 期望：全部成功，输出目录里**没有**残留的 `*.tgconvert-pending`。
2. 模拟"上次没转完"：在某个已转好的装配旁边**手工新建**一个同名标记文件，
   例如输出目录里有 `总装.asm`，就新建空文件 `总装.SLDASM.tgconvert-pending`。
   然后再转换一次同一个文件夹，仍然不勾「覆盖已存在的转换结果」。
   - [ ] 期望：其它文件显示"输出已存在"并跳过；**这个装配被重新转换**，转完后标记文件消失。以前它会被当成已完成直接跳过。
3. 真实中断：转换进行到一半时点「停止」（会直接结束转换进程）。
   - [ ] 期望：正在转的那个文件留下 `.tgconvert-pending` 标记；再次开始转换（不勾「覆盖已存在的转换结果」）时它会被重新转换，完成后标记消失。
4. 转换失败的文件会在输出目录留下看得见的 `.tgconvert-pending` 文件，可以直接删掉，也可以留着让下次自动重转。
