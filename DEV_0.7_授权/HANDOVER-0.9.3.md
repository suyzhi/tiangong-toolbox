# 0.9.3 交接（2026-10-25）：自动更新加「立即更新」

用户原话：「版本更新不应该是一个压缩包的样子吧，应该点击更新插件后自动更新，而不是需要用压缩包重新安装」→ 加「立即更新并重启天工」。

* 「发现新版本」下载好以后：**「立即更新」**（主按钮）/「关闭天工时再装」。直接点 × = 关闭天工时再装。
* 立即更新：确认框 → 等待脚本（`-Restart`）2 秒后给天工发普通关闭请求（`CloseMainWindow`，等于点 ×，没保存的文件天工自己会问）
  → 5 分钟内退出了就装（install.ps1 -Force）并重新打开天工（插件在天工进程里取到的 exe 路径）；
  没退出（保存提示里点了取消）→ 退回"关闭天工时再装"，装完**不**自动打开天工。
* 点工具箱命令时弹的提示里选了立即更新：命令不再打开（天工马上要关）。「检查更新」遇到已下载待装的版本，直接打开到"已下载"那一步，可以立即更新。
* 已经有一个等待脚本在等（先选了关闭时再装、后来又点立即更新）：先结束旧的再起新的。

## 测试

* `--update-restart <假天工>`（tests/fixtures/TianGongFake.cs，进程名 TianGongFake，不碰真天工）8 条：关得掉 → 装 → 重新打开（启动两次）；
  拒绝关闭 → 改成关闭后再装、装完不重新打开。
* 真天工（排队脚本在私有桌面上起的、没开文件）：同一桌面上发关闭请求，**1 秒内退出**。
  注意：等待脚本和天工不在同一个桌面时（只有测试的私有桌面会这样）看不到天工主窗口，关不掉 —— 用户实际使用时同在默认桌面，没有这个问题。
* WMI 起的进程在用户会话（session 1、可交互），弹窗 / 重新打开的天工用户看得见。
* 授权 138、更新 11、自动打孔 UI 926 全过；activation.dat 未变。
