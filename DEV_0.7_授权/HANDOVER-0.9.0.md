# 0.9.0 交接（2026-10-24）：页面 UI 升级 ——「D · 侧栏向导」+ 动效

用户原话：「我喜欢D的版本，然后我想要UI页面加点动态效果。其他的窗口也按照D的来一份吧。设计语言统一一下，然后做完页面后等待另一个正在进行的会话运行完毕后合并进插件，版本号升为0.9.0页面UI升级」

设计稿（四版概念 + D 全套，含可点的动效原型）：https://claude.ai/artifact/GdpW7TYkKipVnXWy2wvyi5
（页「D 全套（0.9.0）」：设计规范与动效、自动打孔 / 配孔检查可点原型、其余窗口静态稿。）

本版只动界面，**不改任何打孔 / 检查 / 转换 / 写属性的逻辑**：原有控件对象、事件、状态全部保留，只是换了摆放位置和外观。
另一个会话的 0.8.5（59ed312）先提交，本版在它之上（开发时用它未提交的改动做基线，最后三方合并，零冲突）。

## 一、设计规范（D）

| 项 | 值 |
| --- | --- |
| 颜色 | 主色 #4F46E5、选中底 #EEF2FF、侧栏 #F7F7F8、分隔线 #E4E4E7、正文 #18181B、说明 #63636B；完成 #15803D/#DCFCE7、警告 #92400E/#FEF3C7、错误 #B91C1C/#FEE2E2 |
| 字体 | Microsoft YaHei UI：正文 9.75pt（13px）、步骤名/按钮 10.5pt、步骤标题 16.5pt 粗、说明 9pt；孔径/坐标/数量用 Consolas |
| 圆角 | 输入/按钮 8、选项块/列表项 10、面板 12 |
| 尺寸 | 控件高 34，主按钮 44；底部操作栏 72 |
| 结构 | 有先后的窗口 = 左侧步骤栏 + 右侧当前步骤 + 底部操作栏；列表类窗口 = 左侧分类/筛选 + 右侧内容 |
| 主按钮 | 只有一个，在右下角，写清楚做什么（「开始打孔 6 个孔」「应用到 6 个孔」「生成 3 块板子」「写入 3 个文件」） |

颜色名沿用老名字（`Ui.Bg / Accent / Warn …`），新加 `Ui.Rail / Subtle / AccentSoft / OkSoft …`，老代码不用改就换上新配色。

## 二、动效

| 场景 | 时长 | 做法 |
| --- | --- | --- |
| 按钮悬停 / 按下 | 120ms | 底色插值 |
| 选中态（分段按钮滑块、组标签、侧栏白块） | 180 / 240ms | 位置、颜色插值，缓出 |
| 切换步骤 | 240ms | 旧页淡出，新页从右（后退时从左）16px 滑入 |
| 步骤做完打勾 | 180ms | 0.6 倍放大到 1，带一点回弹 |
| 列表新增项（在模型里点了孔/面） | 800ms | 浅靛蓝底褪成白 |
| 主按钮进度 | 260ms | 打孔 / 转换时按钮本身变进度条（「打孔中 2 / 3 个面」「转换中 23 / 64」） |
| 提示条 | 200ms + 停 4 秒 | 打完孔 / 转换完从底部弹出，带「撤销本次打孔」「打开输出目录」 |
| 空列表 | 持续 | 虚线框里一个慢慢呼吸的小圆点（「正在等你在模型里点孔…」） |

**原则：动效只管"看起来"。** 状态一律同步改完——切步骤时页面立刻换好，动画只是盖在上面的一张截图（`WizardShell.PageOverlay`）；测试、脚本、PrintWindow 读到的永远是最终状态。
以下情况全部瞬变：Windows 关了「动画效果」（`SystemInformation.UIEffectsEnabled`）、远程桌面、设置目录（`%LOCALAPPDATA%\TianGongCadSuite`，和 panel.log 同一个）里放 `ui.tsv` 写一行 `motion<TAB>0`、测试里 `Anim.ForceOff = true`。

## 三、各窗口

| 窗口 | 改成 |
| --- | --- |
| 自动打孔 | 4 步：参考孔 / 打孔面 / 孔规格（组标签 + 参数 + 孔形状）/ 预览并打孔（数字块 + 结果）。侧栏底部「关联孔位」小卡片；改孔型、撤销、全部重选收进「更多」。**交互仍然没有模式切换**：随时点圆边 = 参考孔、点平面 = 打孔面，点了什么自动翻到那一步、新项闪一下；只要能打，主按钮在哪一步都是「开始打孔 N 个孔」（一键打孔的老习惯不变），还不能打才是「下一步：…」 |
| 批量排孔 | 4 步：打孔面 / 排布（右边实时排孔示意）/ 孔规格 / 预览并打孔。预设挪到侧栏底部卡片；点了新面自动翻到「排布」 |
| 改孔型 | 2 步：要改的孔 / 改成（醒目的「要改 N 个孔 → 新规格」块 + 参数）；点了孔自动翻回第 1 步 |
| 配孔检查 | 侧栏：开始检查 + 四类筛选（漏打孔 / 孔偏了 / 配错孔 / 孤孔，仍可同时勾几类，孤孔默认不显示）+ 复制结果 / 判定口径；标题「发现 N 处问题」；底部「跳转到孔」「去配孔」 |
| 属性卡填写 | 侧栏：载入当前文档 / 添加文件 / 按文件名筛选 / **按状态筛（新）**：全部、改过未写入、缺属性、读取出错（带条数）；底部「写入 N 个文件」 |
| 批量格式转换 | 原来是 WinForms 默认样式，现在 3 步：输入 / 输出设置 / 转换（数字块 + 细进度条 + 日志）；转换完弹提示条 |
| 型材自动填充 | 3 步：型材 / 板子 / 框口（列表 + 位置预览）；读到框口自动翻到「框口」；输出目录在侧栏底部 |
| Lineup 快速录入 | 结构（Dock + 紧凑点选模式）没动，加了左侧类目导航（带条数、查找框、清单状态卡），菜单扁平化，表格/共用字段区换 D 配色 |
| 配做规则 / 判定口径 / 授权激活 | D 对话框：标题 + 内容 + 底部操作栏 |

没动：命令 1「四面生成内嵌板」、命令 4「导出出图训练数据」（都在功能区隐藏着）。

## 四、代码

* `src/UiShell.cs`（新）：`Anim` 动效引擎、`StepRail` 步骤栏/分类导航、`WizardShell` 整窗骨架（侧栏 + 标题 + 页面 + 操作栏 + 提示条）、`ActionBar`、`Toast`、`Flash`、`ChipTabs`、`StatTile`、`EmptyHint`、`SlimProgress`、`RailCard`、`RoundBox`。
* `src/UiKit.cs`：D 配色 / 字号；`FlatButton` 自绘圆角 + 悬停渐变 + 进度；`Segmented` 滑块；`Card` 圆角细边 / 浅灰填充；`ToggleChip` 侧栏样式。
* 各窗口只重写了 `BuildLayout`（和 PropCard / 格式转换的构造函数里的布局段）；点选入口外面包了一层（`AcceptPick` → `AcceptPickCore` + 自动翻页 / 闪一下）。
* 测试钩子：`GoPageForTest(i)`（自动打孔 / 批量排孔 / 改孔型 / 型材填充 / 格式转换）、`AutoHoleForm.PageForTest`。
* WinForms 小坑：直接 `Dock=Fill` 放进页面的面板，`Resize` 在构造后不一定会再触发——摆子控件用 `Layout` 事件（型材填充第 1 页就是这么翻车的）。

## 七、没做 / 下次注意

* 数值框、下拉框、表格是系统控件，只换了字体/边框/配色，没有做成完全自绘的圆角输入框。
* Lineup 只做了"轻量 D"（没改成分步骤），它的紧凑点选模式会改窗口大小、显隐一堆控件，整体重排风险大。
* 动效在打孔中（UI 线程忙着跑 COM 调用、只在每张面之间泵一次消息）会一顿一顿，这是正常的。
