# SolidWorks / STEP 批量转换为天工格式（DEV 0.5.1）

把 SolidWorks 的装配（.SLDASM）、零件（.SLDPRT）、工程图（.SLDDRW）以及 **STEP（.stp/.step）**
批量转换成天工 CAD 的原生格式（.asm / .par / .psm / .dft），转换结果自动落盘，下次直接打开
天工文件，不需要再转换一遍。

- 独立程序：`TianGongConverter.exe`（不需要天工 CAD 已启动，双击即可用）
- 插件命令：天工 CAD 功能区「插件（加载项）→ 功能 → 批量格式转换」（命令 ID 5）
- 支持两种输入：SolidWorks 用天工自带的 SolidWorks 转换器，STEP 用天工自带的 STEP 转换器，
  走的是同一条流水线。STEP 的顶层文件按导入结果自动决定输出是 .par 还是 .asm。

## 1. 它解决什么问题

天工 CAD 打开 SolidWorks 文件是在**内存里**完成转换的：

- 转换出来的文档 `FullName` 只有名字、没有磁盘路径，也就是「未保存」状态；
- 不点保存，退出后结果就丢了，下次还要从头再转一遍；
- 一个装配里每个零件（.par）都是独立文档，要逐个保存；
- 一次只能盯一个文件，多个装配体要反复手工操作。

本工具对每个输入文件调用天工 CAD 自带的转换器打开，然后把转换出来的**全部文档**
（顶层装配 + 所有子装配 + 所有零件）写到指定目录，再关闭。STEP 文件同样如此：一个带装配结构的
.stp 会转换成 1 个 .asm + 若干 .par，单个零件的 .stp 就只产生 1 个 .par。

## 2. 算法与复杂度

```text
扫描输入            O(文件数)            每个目录只遍历一次
任务划分            O(n log n)           按输入目录分组后 LPT 配平
每个文件：
  打开并转换        O(1) 次 COM 调用     耗时 = 天工 CAD 转换 Parasolid 的时间（瓶颈）
  遍历文档树        O(文档数)            按 FullName+Type 去重
  保存              O(文档数) 次 SaveAs  后序遍历：先零件、后装配
  关闭              O(文档数)
```

- 每个文件只打开一次，每个文档只保存一次；没有重复遍历，没有重复转换。
- LPT（最长处理时间优先）配平后完工时间不超过最优解的 4/3，代价只有一次排序。
- 工具自身开销只有每个文档 4~11 ms 的 SaveAs 调度。**处理时间瓶颈就是天工 CAD 转换的效率。**

## 3. 使用

### 3.1 独立程序（推荐）

1. 双击 `TianGongConverter.exe`；
2. 「添加文件夹…」选择装着 SolidWorks 文件的目录（可按住 Ctrl 一次多选多个站位目录，或直接把多个站位文件夹拖进窗口），或「添加文件…」挑单个文件；
3. 第 ② 步选择输出位置（默认「各自源文件夹（原地）」，多站位各自在自己的文件夹内转换；也可切为「各自建子文件夹」或「统一输出到指定目录」）；
4. 默认勾选：包含零件、包含装配、包含 STEP、包含子文件夹；
5. 点「开始转换」。结束后写出 `转换报告-<时间>.csv`，每行一个文件的状态与耗时。

不用管天工 CAD 是否已经打开：工具会自己拉起**隐藏的** CAD 进程，不占用你正在用的窗口。

### 3.2 插件方式

运行 `安装.cmd` 后重启天工 CAD，功能区「插件（加载项）→ 功能」出现
「批量格式转换」，以当前文档所在目录作为默认输入。

## 4. 输出位置与目录结构

支持三种输出位置模式（窗口自动记住上次选择，下方实时预览每个输入目录的落盘位置，双击可直接打开）：

1. **各自源文件夹（原地，默认）**：添加多个站位（如 `D:\项目\ST01`、`E:\项目\ST02`）时，每个站位直接转换到各自源文件夹内（子目录里的文件留在各自子目录，不额外套层、不拉长路径）；同一站位内自动串行防锁碰撞，不同站位之间仍多进程并行。
2. **各自建子文件夹**：每个站位各自输出到 `各自源目录\<子文件夹名>`（默认 `天工格式输出`，保持源目录 0 残留），且递归扫描自动跳过输出子文件夹防止重复扫入。
3. **统一输出到指定目录**：汇总到指定总目录。勾选「镜像源目录结构」且添加多个输入文件夹时，自动按站位文件夹名分子目录（如 `输出目录\ST01\`、`输出目录\ST02\`；末尾重名时自动带上级目录名消歧）：

```text
输出目录\
  ST01\                  <- 对应源目录 ST01\
    Part1.par
    组件.asm
    总装.asm
    总装.cfg
  ST02\                  <- 对应源目录 ST02\
    ...
```

装配引用零件的路径会在保存时**自动指向输出位置**，所以输出目录可以整体拷走，直接打开
`.asm` 就能用。实测：重新打开转换后的装配，6 个顶层引用全部命中新目录，FileMissing=False；
STEP 装配体用「转换后重新打开校验引用」跑过同样通过（15 个文档、0 丢引用）。

- 取消「镜像源目录结构」= 结果平铺在一个目录（同名会覆盖）。
- 「覆盖已存在的转换结果」默认关闭：**输出已存在就跳过**，所以中断后重跑只补没做完的。
- 「转换后重新打开校验引用」：转换完再打开一次输出装配，确认没丢引用，适合关键批次。

## 4.1 STEP（.stp/.step）输入

- 界面上的「STEP .stp/.step」默认勾选，和 SolidWorks 的三种扩展名可以混在一批里转换。
- **输出扩展名由导入结果决定**：STEP 只描述几何，不说明"这是一个零件还是一个装配"。工具在打开
  文件后读取天工 CAD 实际产生的文档类型再决定顶层文件名，所以同一批 .stp 里，单个零件出
  `X.par`，带装配结构的出 `X.asm` + 若干 `X.par`。实测 7 个 STEP 中有 3 个是装配体，全部识别正确。
- **断点续做同样适用**：因为 .stp 可能是 .par 也可能是 .asm，工具会把两个候选名都检查一遍，
  已经转换过的 STEP 第二次运行直接跳过（实测 7 个 STEP 重跑全部跳过，15.6 秒里 13.5 秒是 CAD 启动）。
- 速度比 SolidWorks 快得多：本机实测 7 个 STEP（60 KB ~ 5 MB，含 3 个装配体）共 69.3 秒（含 CAD
  启动 13.5 秒），平均每个文件约 8 秒；其中打开+转换占 75%~92%。

## 5. 提速与并发架构（实测）

### 5.1 核心提速机制

1. **启动前预跳过 + 结果落盘**（二次续跑耗时接近 0）。在启动任何隐藏 CAD 进程之前先做 `ConvertPlanner.FilterPending` 存在性校验；整批已转过时直接 **< 0.1 秒**结束（旧版要先花 ~13.5 秒启动 CAD 再逐个跳过），实际拉起的进程数也不超过剩余待转文件数。
2. **并行预拉起隐藏 CAD + ROT 就绪探测**（多实例启动提速 **3~4 倍**，且彻底纳入 Windows 作业对象）。
   - 过去每个 worker 直接调用 `CoCreateInstance("SolidEdge.Application")`，由于天工 CAD 注册为 `REGCLS_SINGLEUSE`，Windows DCOM SCM 会严格**串行**拉起实例（每多 1 个多等 ~24 秒，4 实例要近 100 秒），且 DCOM 进程不受作业对象管辖。
   - 现在由主控直接并发拉起 `N` 个 `TianGong.exe /automation -Embedding` 并立即加入 `NativeJob`，worker 只读轮询 ROT 直到全部就绪后在 `~0.01 秒/个` 内完成 COM 绑定，同时严格隔离用户已打开的交互式天工窗口；实测 3 实例同步启动仅 **~21~25 秒**，停止或异常退出零孤儿残留。
3. **热驻留常驻工作池（`WarmConvertPool`）**（连续批次 **0.00 秒**启动 + 跳过转换器 DLL 冷初始化，小/中批次总耗时再砍一半）。
   - 界面默认勾选「热池驻留」：转换窗口打开期间，已启动并预热好 STEP / SolidWorks 转换器的隐藏 CAD 常驻待命；连续转换下一批文件夹时在 **0.08 秒**内唤醒，仅在并发需求高于当前池数时按差额并行扩容。
   - 安全生命周期：空闲 **5 分钟**自动退出释放内存；底部提供「释放驻留 (N)」随时手动回收；点「停止」、关闭窗口或主进程异常退出时由 `NativeJob` 作业对象与 `WorkerChildren.Kill` 保证 **0 残留**。
4. **无锁动态任务队列 + 装配体相位屏障 + SolidWorks 源主干跨进程去重**（消除静态分桶的长尾空等与 `_0`/`_5` 后缀导致的重复转换）。
   - 动态队列 `ConvertQueue` 按「`0=装配 .sldasm` → `1=STEP` → `2=独立零件 .sldprt` → `3=工程图`」且同类内大文件优先（LPT）动态抢占；装配阶段未完成前暂缓 `.sldprt` 抢占。
   - 解决天工 SolidWorks 转换器因 `MRUex` 历史自动给同名零件/子装配追加 `_0`/`_5` 后缀导致跨进程去重失效的问题：通过 `ConvertPlanner.ResolveSolidWorksSource` 精确比对磁盘源文件（保留本身带数字后缀的真零件如 `Bolt_2.sldprt`），首个进程将带后缀组件归一回干净原名落盘，并发装配保留后缀避免写冲突与断链，且均把真实源路径写入跨进程 `ConvertWrittenIndex`（`MarkSource`），后续独立 `.sldprt` 与已转子装配 `.sldasm` 全部毫秒级跳过（164 件项目实测直接跳过 **88 件**，覆盖/续跑模式均生效）。
5. **大型站位装配专项防卡顿与防假失败（2026-11-25 实测优化）**：
   - **同目录大装配串行化（`.d<hash>`）+ 重型装配实时内存门控（`.h`）**：大型站位目录（含 ≥5 MB 装配或同目录 >8 个装配，或同目录输出）自动由单进程按最大总装优先串行打开，避免多进程重复翻译同一批 100~215 MB 超大零件与源目录 `.par` 写锁碰撞；其余进程自动绕过忙碌目录去并行消化独立 STEP 或其他站位；多个重型站位并发时按真实可用物理内存动态门控（预留 ≥5 GB/实例、实时可用 <5.5 GB 时排队）。
   - **重型装配期间空闲进程主动释放 CAD 内存**：当其他进程正在转换大型装配而本进程已无活可干（如已转完独立 STEP）等待超过 8 秒时，自动释放自身空闲 CAD 回收数 GB 物理内存让给总装（实测即时回收 **3.2 GB**），总装结束后无 CAD 零秒跳过全部已转零件、仅在确有未转件时按需重启；连续批量运行空闲内存 ≥4 GB 时亦在文件间隙主动重启防泄漏。
   - **智能防误拷与精确缺件诊断**：大型装配普遍自带少量缺失参考件，不再盲目把含零件的站位目录向上越界拷贝 3,000 个无关文件到 `C:\Temp\stage-*` 并丢弃十几分钟的重开成果；仅在 `StageCanSupplyMissing` 实查确认其他子目录确有缺失文件时才暂存。空壳装配不再无效重试 4 次，直接从天工转换日志解析并报出具体缺失的源文件名。
   - **保存冲突自愈 + 源目录零残留自动清理**：`RetrySave` 对瞬时 `0x80020009 (DISP_E_EXCEPTION)` 增补退避重试；大装配（打开 ≥60 秒）若仅个别子件保存失败但 CAD 仍存活，仍保留顶层装配落盘不白废十几分钟；输出到独立目录时，关闭文档后按打开前快照自动清理天工 `Open()` 落在源目录里的临时 `.par`/`.asm`/`.log`（含被抑制子件与 STEP 日志），源目录保持 **0 残留**；同目录输出模式下对已落盘且未脏的子装配免重复 `SaveAs`；修复同名 `.sldasm`/`.sldprt` 共存时的源主干映射碰撞，嵌套深度遍历上限提升至 32 层并增加重复紧固件路径缓存与实时进度日志。
6. **去全局保存锁 + 跨进程开档节拍保护 + 单遍树遍历 + 无头会话调优 + 崩溃自愈**。
   - 取消跨全机的单一 `SaveAs` 互斥锁，改为按目标路径哈希的细粒度锁 + 顶层 SolidWorks 目标预占位 + 瞬时锁定退避重试（`STG_E_LOCKVIOLATION` / `RPC_E_SERVERFAULT`），不同文件落盘 100% 真正并发；
   - 增加跨进程 `PaceOpen`（最小间隔 1.0 秒，正常异步流转 0 ms 等待），规避天工 2025 多实例在同一时刻切入文档环境并发读写用户主题 XML 导致的异常退出，同时绝不修改用户的停靠面板布局（不触碰 `EdgeBarVisible`/`StatusBarVisible`）；
   - 合并 `EmptyAssembly` 与 `BuildNode` 为单遍 COM 遍历，隐藏会话关闭交互与界面重绘（`Interactive=false`、`DelayCompute=true`、`StatusBarDelayUpdate=true`、`DisplayRecentFiles=false`、`UndoSteps=0`），先关顶层文档 `Close(false)` 批量释放子文档并在 `/automation` 模式下跳过插件后台更新检查；
   - 若某个隐藏 CAD 在异常模型上崩溃断开，worker 自动重建会话继续处理剩余队列。

## 7. 安全设计

- 工作进程与并行预拉起的隐藏天工 CAD 实例**全部直接纳入同一个 Windows 作业对象（`NativeJob`）**：无论点「停止」、关闭窗口还是主进程被强杀，都会随作业对象自动整体结束，不再残留孤儿 CAD。
- 若个别环境回退到 DCOM 启动或触发会话自愈重建，停止/关窗时仍会通过 `WorkerChildren.Kill`（按已知子 CAD PID 与 `/automation` 启动时间窗，严格跳过转换前已存在的用户天工进程）兜底回收，用户自己打开的天工窗口绝不会被误杀。
- 预拉起绑定阶段严格校验 `forbiddenPids`（启动前已存在的用户 CAD），保证转换器绝不误连或关闭用户正在编辑的模型。
- 同一个输出文件用认领锁 + 按目标路径哈希的细粒度命名互斥体保护，多个进程不会同时写同一个文件，不同文件之间则零互斥阻塞。
- 输出目录与源目录不要互相嵌套，避免把自己的输出再扫进来。
- 失败的文件会自动重试一次（隐藏 CAD 崩溃时自动重建会话再重试），并在 CSV 报告里记录具体错误。

## 8. 已知边界

- 转换速度取决于天工 CAD 自带的 SolidWorks / STEP 转换器，本工具通过并行预拉起、动态队列、去全局锁与无头调优最大化多核并发吞吐，不改变底层几何内核。
- 源装配缺引用的零件时，天工 CAD 打开就缺件，工具照常保存已有文档并在报告里记录。
- 工程图（.SLDDRW → .dft）默认不转换，需要时勾选。
- 天工 CAD 的 SolidWorks 转换器在打开装配时（`Output in the same folder=On`）会把临时 `.par`/`.asm`/`.log` 写到源文件旁边；当本工具的输出目录与源目录不同时，转换并关闭文档后会按打开前快照**自动清理本次新生成的源目录临时副本**（绝不误删源目录原有文件），使源目录保持干净；若选择直接输出到源目录则保留转换结果。
- 并发度过高（如笔记本上强行开 6~8 进程）会因 TDP 降频与磁盘/内存竞争出现收益递减，建议保持「自动（智能并发，推荐）」。
