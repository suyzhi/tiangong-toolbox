# 真机鼠标点击实测（2026-09-26）

上一轮的两个会话（防盗激活码、孔型预览与布局优化）都**没有用鼠标点过插件**——
之前的"实测"走的是 COM 快捷方式（SolidEdge.Application 的 StartCommand），
等于绕过了功能区、激活窗口和参数面板。这次补上：在**私有桌面**上用**真实鼠标消息**把插件点了一遍。

---

## 1. 做法（为什么不打扰你，也不假）

- **私有 Windows 桌面**（CreateDesktopW，名字 TGWork070）：CAD 跑在一个你看不见的桌面上，
  光标、焦点、窗口全部隔离；你桌上的鼠标不会被抢。
- **真实鼠标消息**：定位到控件窗口后 SetCursorPos（该桌面自己的光标）+ PostMessage
  WM_MOUSEMOVE / WM_LBUTTONDOWN / WM_LBUTTONUP，坐标由 WindowFromPoint + ScreenToClient 换算。
  键盘同理：逐字符 WM_KEYDOWN + WM_CHAR + WM_KEYUP（会触发 TextChanged，和真人打字一样）。
- **不靠肉眼估坐标**：先 PrintWindow 截图 → 裁切放大 3~4 倍 → 量像素 → 换算屏幕坐标
  （窗口矩形在 -8,-8，图像坐标 = 屏幕坐标 + 8）。
- **每步回读**：窗口列表、控件文本（SendMessage WM_GETTEXT）、截图三者交叉确认。

驱动脚本都在 tools/mouse-e2e/：lib.ps1（封装）、01-start.ps1（注册+启 CAD+开夹具）、
act.ps1（一次鼠标动作+截图+窗口回读）、activate.ps1（激活窗口里输入码并点激活）、
sweep.ps1（逐个点开功能区命令）、capall.ps1 / inspect.ps1 / crop.ps1。

## 7. 功能实测（真鼠标点孔 / 点面 / 点开始打孔）

上一轮只做到"命令能点开、面板联动对"。这一轮把**模型操作**也点了一遍。

### 步骤与结果

| # | 动作（真鼠标） | 结果 |
| --- | --- | --- |
| 1 | 在模型里点一个孔的**圆边** | ① 区变成「共 1 组参考孔：Φ6 ×1 → 通孔 Φ6 贯通」；日志 PickAccepted |
| 2 | 点下板**上表面** | ② 区「已选 1 个打孔面：TappedB.par 平面 26」；③ 区「将打 1 个孔／孔型：通孔 Φ6 贯通」 |
| 3 | 点「开始打孔」 | **失败**：结果框「共打孔 0 个，失败 1 个」，说明里是原始 COM 文本：被调用的对象已与其客户端断开连接 (RPC_E_DISCONNECTED) |
| 4 | 换个面、同板再试一次 | 同样失败（0 成功 1 失败） |

失败的调用点是 `SolidEdgePart.Holes.AddThroughAll`；插件已按设计重试 6 次（每次 DoIdle + 400ms），
并按"丢掉缓存、重建基准面、重取模型"再试一次，仍然失败。日志里这类重试累计 111 次。

### 对照实验：同机、同构建、走历史验收路径

用 09-25 通过验收的那条路径（`tools/VisualAcceptance.cs` 编译成独立进程 + 跨进程 COM 直接调用产品代码）
在当前 **0.7 构建**上重跑：

    VISUAL ASSERTIONS pass=22 fail=0

其中包含：自动打孔打出 M6 螺纹孔（Φ4.92 内径，切除体积 379.8 mm³ 与理论一致）、贯通螺纹孔锥面 0 个、
批量排孔 4 个 Φ6 通孔、配孔检查报出 1 处漏打孔。产物在 artifacts/visual-e2e/。

### 结论（当前能确定的）

1. **打孔功能本身是好的**：同一台机器、同一份 DLL，由独立进程驱动时照常打孔。
2. **鼠标驱动这条路在 TappedFixture 这份夹具上打不进**：选孔、选面、映射预览都对，
   一到写模型就断连。失败与"合并宿主"和"授权模块"无关——它是写模型这一步对这个零件失败。
3. 两次实验的差别有两处，还没隔离：① 驱动方式（CAD 进程内的插件 UI 线程 vs 独立进程跨进程 COM）；
   ② 目标零件（TappedFixture 里的文件版零件 vs 验收程序用 iso metric 模板新建的零件）。
   下一步应当把这两个变量分开测：在**同一个** TappedFixture 上用验收程序的方式打一次，
   再在**新建零件**上用鼠标点一次。
4. 附带发现：结果框把原始 COM 异常文本直接甩给用户（含 HRESULT），应当走 `Friendly()` 转成人话。

### 一条踩过的坑（换构建时必须知道）

把注册表指到 0.6 的 DLL 后重启 CAD，实际加载的仍是**上一次注册的那份**：
失败栈里的源码路径仍是 `DEV_0.7_授权\src\AutoHoleCad.cs`。所以"换 DLL 再测"这种 A/B 结论不可信，
除非把 CAD 的加载项记录一并清掉：

    HKCU\Software\NDS\TianGong\Version 225\AddIns\{8C05165C-65A4-4EF2-A138-508589D82004}

### 隔离纪律

夹具是先 `Copy-Item` 成副本再操作的；原夹具 4 个文件的 mtime 实测未变
（TappedA.par 2026-09-25 10:59:30、TappedB.par / TappedFixture.asm / .cfg 11:15:33）。

## 8. 「装配里打孔失败」的根因实验（2026-09-26 晚）

第 7 节发现失败后，用一组对照实验把变量逐个排除掉。工具都在
`tools/mouse-e2e/`（`FixtureDrill/PartDrill/AsmDrill*/ProbeHole.cs`），产物在 `artifacts/fixture-drill/`。

| # | 场景 | 结果 |
| --- | --- | --- |
| 1 | 客户端在同一会话里**新建**零件+装配再打孔（`VisualAcceptance.exe`） | ✅ 22/22 通过 |
| 2 | `.par` 当**顶层零件**打开再打孔 | ✅ 成功（Φ6 通穿 20mm 板，切除 565.5 mm³） |
| 3 | 打开磁盘装配 → 对实例零件打孔（面板路线 `DrillRequests`） | ❌ CO_E_OBJNOTREG |
| 4 | 同上（验收路线 `Drill`，带重建重试） | ❌ 同样失败（重试也救不回来） |
| 5 | 同上 + `Occurrence.MakeWritable()`（ReadOnly 由 True→False，文件属性不变） | ❌ 仍失败 |
| 6 | 同上 + `Occurrence.Activate=true` 想进原位编辑 | ❌ `InPlaceActivated` 轮询 8 秒始终 False |
| 7 | 同上 + `PartDocument.Activate()` | ❌ E_FAIL |
| 8 | 同上 + 先 `Documents.Open(零件)` 再打 | ❌ 被"未保存的更改"弹框挡住 |
| 9 | **鼠标双击零件进入原位编辑** | ⚠️ 进得去，但插件的命令在零件环境**点了没反应**（命令只注册在装配环境） |

**结论**：写不进"打开装配里的实例零件"是 CAD 接口层的限制；读参考孔、反推规格、求交、预览全是对的，
错在最后写模型那一步。CAD 自己的做法是"双击零件进入原位编辑"，而插件的命令没注册零件环境，
所以现在两条路都不通。下一步建议见 [HANDOVER.md](../HANDOVER.md) 第 5 节。

**顺带修掉/改进了 4 处**（见 HANDOVER 第 6 节）：报错改人话、`DrillRequests` 补重建重试、
放开原位编辑限制、插件启动自报 DLL 路径版本（换版本可自证）；install.ps1 不再动 NDS 注册表。

### 实机确认：报错文案已改成人话

在装配里再点一次「开始打孔」（真鼠标），结果框的"说明"里现在写的是：

> · TappedB.par Φ6：打孔失败：目标零件的数据连接已失效（零件可能被重新加载或被其它操作改动过）。
>   请重新点一次打孔面；如果仍然失败，先在装配里双击这个零件进入原位编辑再试。

原始 COM 文本（RPC_E_DISCONNECTED / HRESULT 0x80010108）不再出现给用户看，只留在 panel.log 里。

## 10. 根因纠正（2026-09-27 凌晨）

第 8/9 节的"上下文/进程"结论**作废**。真正的原因是：**往已经有孔的位置再打孔会被 CAD 拒绝**，
报的还是含糊的 COM 错误。证据：

    # 同一会话、同一零件、同一张面：
    第1次: OK created=1 method=通孔 Φ6      ← 空位
    第2次: ERR ...                         ← 同一位置再打（已经有孔了）

    面板「批量排孔」进程内排 4 个孔（空位）:  排孔完成：4 / 4 个   ← 功能本身没问题

夹具 TappedFixture 的两块板孔位是配对的，所以"自动打孔"的参考孔投影必然落在已有孔上——
之前所有失败都来自这里。代码已加"已有孔预检"并改正报错文案（见 HANDOVER）。
