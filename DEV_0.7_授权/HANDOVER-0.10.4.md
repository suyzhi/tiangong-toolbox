## 三、没做 / 已知

1. **格式转换往 SolidWorks 源文件夹里写文件**（这一轮在副本上发现，H 盘原件没被我们动过）：转 L1-ST140 1.03 / 1.10 时，源文件夹里多出 `3491999__1498__SCHILD_8X30_0397.par`、`…_0904.par`、`…_0905.par`、`3C21295__0103__BRIQUETTE.par`、`3C21295__0231__CONNECTION.par`，还有天工自己的 `TGImportFile.log`、`<装配名>.log`。
   * 猜测（没验证）：`FormatConvertCad` 里「同一零件的重复实例，已并入」直接 `continue`，那份文档没存；存上一级装配时天工把没存过的子文档存在它**分配的位置（源文件夹）**。名牌 SCHILD 这种一个装配里用很多次的零件最容易中。BRIQUETTE / CONNECTION 先被这样存到源文件夹，轮到它们 SaveAs 到输出目录时「发生意外」，整个装配算失败，重试又在输出里多出一批 `…_0.par`（1.03 输出里 132 个）和一个 `.tgconvert-pending`。
   * 要查：转完的输出装配引用的是输出里的零件还是源文件夹里那几个（天工文件是压缩的，按字节扫不出路径，要用 `AsmList` 在 CAD 里列）；重复实例改成存到同一个输出文件或先存再丢；转换前后对源文件夹拍快照，新冒出来的天工日志删掉、零件挪到输出。
   * H 盘 `L1-ST100-MIX-20260324-0325\TGImportFile.log`（3 月）是用户自己以前转的，不是这几轮测试留下的。
2. **型材自动填充认不出 SolidWorks 转来的铝型材围栏**（ST064 三个 FENCE GUARD 都是 0 个框口）。没查原因：可能是 SolidWorks 模型里角部有间隙 / 角码、也可能是几百个实体的导入型材读不对轴线和长度（跳过的那些全是这种）。下一步：对其中一个平面用 `PanelScanE2E` 加日志看每根型材读出来的轴线 / 端点，和天工里量的比。
3. 高 DPI（同前）；葫芦孔；SolidWorks 工程图天工打不开。
4. 「不查的零件」只按名字。外购件和自制件之间的配错孔照样报（有些是真问题，有些是外购件模型画法，比如 M12×1 细牙螺母内径对 M12 粗牙底孔）。

新探针 / 测试入口：
* `tools/hole-feature-probe/CheckTimingInProc.cs` + 开发构建的 `Diagnostics.StartCheckTiming(path)`：进程内跑配孔检查，分阶段、最慢的 15 个零件（边数 / 实体数）、射线最费时的 20 个零件；配对阶段每 20 s 往 `%TEMP%\tg-check-timing.txt` 写进度（跑很久时看这个，别盯 queue.log）。要注册开发构建。
* `PartRayTarget.Casts / CastTicks`：每个零件问了 CAD 几次、花了多久（常开，开销可以忽略）。
* `RenameE2E generic <副本根> <装配相对路径> <查找> <替换>`：任意装配改名后逐层核对。
* 测试纪律：进程外（CheckCompare）比进程内慢 10～20 倍（NOK 138 s vs 8 s），判断"慢不慢"一定量进程内。
