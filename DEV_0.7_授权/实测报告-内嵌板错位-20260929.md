# 实测报告：型材自动填充出来的内嵌板「错位、大小也不对」（2026-09-29）

> 被测对象：`H:\桌面\SK26.01\SK26.01Lineup\OK310-0924\3号子围栏.asm`
> 测试方式：**真机 + 真 CAD 实例**（私有桌面 TGWork070，全程只操作副本，原文件字节不变）
> 结论一句话：**根因不在几何算法，而在"把生成的板子插进装配"这一步**——天工 CAD 的
> `Occurrences.AddByFilename` 是**按文件名**去查找文件的，装配所在目录里只要有一个同名旧板子，
> CAD 就会把**那个旧零件**插进来：位置用新算的矩阵（对），几何却是旧文件的（错）。
> 于是看到的就是"板子放在框口位置上，但尺寸不对、边跑到型材外面"。

## 1. 现场看到的现象与数据

用户文件里**已经保存着 14 块旧板子**（填充板_001~004、011 的实例），它们与今天的框口对不上：

| 装配里的板子 | 位置（装配坐标） | 今天该格的实际尺寸 | 差异 |
| --- | --- | --- | --- |
| 填充板_001.par:2（722×1232） | Z 2.341 ~ 3.573 | 顶排格 1092×951.3 | 高多 281mm，直接伸到围栏顶以上 |
| 填充板_003.par:2（1337×952） | X -1.581 ~ -0.244 | 该格只有 982 宽 | 宽多 355mm，跨到隔壁格 |

也就是说：**位置是"今天的格"，尺寸是"以前那版设计"的**——这正是"
位置对、几何错"的特征（而不是几何算法算错：算错的板子会是"位置和尺寸一起错"）。

## 2. 真机复现（修复前）

1. 副本放开：`C:\temp\tg-e2e\ok310\fence3.asm`（整目录 4GB 复制，装配目录里保留着用户历次批次
   留下的 `填充板_001.par … 填充板_013.par`——这正是现场条件）。
2. 在 CAD 里选中整圈型材（框架_1 的 19 根 + 框架_2 的 2 根 = 21 项，与用户操作一致）。
3. 点插件选项卡「型材自动填充」→ 面板显示 **"识别到 14 个闭合框口"**（说明几何检测这一步是对的）。
4. 点「批量保存并插入全部框口」，输出到 `C:\dsh-tmp` → 提示"已生成 14 块板子"。
5. 回读这 14 个实例真正绑定的文档：

```
-- 填充板_008.par:1
   文档路径 C:\temp\tg-e2e\ok310\填充板_008.par      ← 不是本批次目录里的那份！
   零件尺寸 982.000 x 1192.000 x 4.000 mm              ← 旧文件的几何
（本批次真正生成的 `C:\dsh-tmp\自动填充_20260929_123050_c32ff3b2\填充板_008.par` 是 982×972）
```

同一批里 001~013 号**全部**被劫持到装配目录里的同名旧文件，只有 014 号（装配目录里没有同名文件）
绑对了——这就是"错位、大小不对"在实机上的直接来源。

## 3. 根因

```csharp
assembly.Activate();
occurrence = assembly.Occurrences.AddByFilename(path);   // path 是本批次新文件的绝对路径
occurrence.PutMatrix(ref matrix, true);                 // 位置是刚算的 → 位置对
```

天工 CAD（Solid Edge 内核）在 `AddByFilename` 里**按文件名做文件查找**：先看装配所在目录，
再看文件查找路径，命中了就用那个文件；我们给的那条绝对路径**不保证优先**。
装配目录里躺着 `填充板_008.par`（旧设计），于是：
**位置 = 新算的矩阵（正确），几何 = 旧文件里的旧板子（错误）** → 用户看到的"错位 + 大小不对"，
而且 CAD 不报任何错、面板还提示"已生成 14 块板子"。

决定性实验（同一台机器、同一份代码，只改文件名）：

| 实验 | 目标文件名 | 结果 |
| --- | --- | --- |
| A（复现） | `C:\dsh-tmp\probe-insert\填充板_008.par`（与装配目录里的旧文件同名） | ❌ 实例绑定到 `ok310\填充板_008.par`，实体 982×1192（我们要的是 500×400） |
| B（对照） | `C:\dsh-tmp\probe-insert\填充板_20260929_ABC_008.par`（唯一名） | ✅ 实例绑定到刚生成的文件，实体 500×400 |

> 附带发现（不是根因，但会让现场更乱）：这台机器上还注册着**两个更早版本**的同一款插件
> ——`矩形板 (DEV 0.1.2)`、`矩形板 (DEV 0.3.0)`（GUID `{98BF0FA8…}` / `{B3B28C54…}`）。
> 它们的按钮也叫「生成矩形板」「多型材自动填充」，点错了就走到旧代码上；旧版里有同一个按名查找的坑。
> 见第 6 节的两条清理建议。

## 4. 修复（改动很小，都在"生成/插入"这一步）

| 文件 | 改动 | 为什么 |
| --- | --- | --- |
| `src/AutoPanelForm.cs`（BatchPanels.Generate） | 板子文件名从 `填充板_001.par` 改成 `填充板_<批次时间戳>_001.par`；`尺寸清单.csv` 同步用新名 | 让每批文件名**天然唯一**，从根上不出现"与装配目录里旧文件同名" |
| `src/CadInterop.cs`（CadBuilder.Generate） | 插入后回读实例真正绑定的文档路径，与刚生成的文件不一致就**撤回实例 + 撤回文件 + 明确报错** | 护栏：万一将来又撞名（或用户手动命名"生成矩形板"撞名），也不会静默插入旧零件 |
| `src/PanelNaming.cs`（新增） | 命名规则单独成类（不依赖 CAD） | 让纯逻辑测试能盯住它，防止有人改回只带序号的名字 |
| `tests/PanelNamingPureTests.cs`（新增）+ `tests/pure/*` | 10 条断言：时间戳格式、唯一性、不含旧式 `填充板_001.par` | 回归 |

护栏的报错文案（真机实测过）：

```
天工 CAD 没有使用刚生成的板子，而是按文件名找到了另一个同名零件：
C:\temp\tg-e2e\ok310\填充板_008.par
装配所在目录里如果有同名零件，CAD 会优先用它。请更换输出目录，或给板子换一个不重名的文件名。
（本批已插入的板子与刚生成的 PAR 会被撤回。）
```

## 6. 给用户的两条操作建议

1. **旧板子要清掉再重播**：这个装配里 9/15~9/23 那几批板子（`填充板_001.par` 等，尺寸来自更早的
   围栏设计：顶排还按 1232 高做的）跟今天的设计不匹配，属于**历史遗留**。建议删掉这些实例
   （以及装配目录里对应的旧 `填充板_*.par`），再用新版重新生成一次。
   现在的版本生成的名字带时间戳，不会再和旧文件重名。
2. **卸载两个旧版插件**（可选但推荐）：`矩形板 (DEV 0.1.2)`、`矩形板 (DEV 0.3.0)` 与本插件功能重叠、
   按钮同名，容易点错。脚本：`DEV_0.7_授权\tools\uninstall-old-addins.ps1`（只删这两条注册记录，
   不动现行版本，也不动 NDS 的其它加载项）。
