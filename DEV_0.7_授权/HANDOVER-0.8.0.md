# 0.8.0 交接（2026-10-23）：新命令 10「属性卡填写」

## 0.8.2（同日）：写装配时一个文件弹一个「加载后已被其他用户修改」，补属性全部失败

用户原话：「这是怎么回事？我感觉当前插件的这个功能根本没法用啊」（截图：写入中 64 …，天工弹框
「…YF25.07G01-L1-M30-02-18.par 加载后已被其他用户修改。由于存在覆盖数据的风险，因此不能授予写权限。」）

两个毛病叠在一起（panel.log + 加密副本真机复现）：

* **补属性全失败**：写入循环第一个文件是当前打开的总装配，属性组件打不开 → 退回改内存，在内存文档的属性集合上用了 `dynamic`。
  内存文档和属性组件的属性集合是**同一个接口类型、成员编号不同**；.NET 的 dynamic 按接口类型缓存调用方式，
  之后属性组件的 `Add` 就调到了错的成员（`TargetParameterCountException`，日志里只记了「调用 Add 时出错」）。
  于是凡是要补属性的文件都退回改内存；用户没保存装配就关了 CAD，这部分全丢。
  0.8.0 / 0.8.1 的单文件探针（`PropCardWriteTest`）每次新进程只写一个文件，碰不到这个顺序，所以没测出来。
* **弹框**：不用补属性的文件（如 02-18）磁盘写成功，接着把内存那份也改一遍 —— 这个零件在取 `OccurrenceDocument` 时已经加载，
  磁盘在加载之后被改了，天工拒绝给写权限并弹框，每个文件一次。
  复现要按原顺序（先取实例文档 → 写盘 → 改内存），开发构建 `StartPropCardOldOrder` 就是它；先写盘后取文档不会弹。
  **隐藏 CAD 不弹这个框**，要在私有桌面 TGWork 上起可见 CAD（scratchpad 的 `run8.ps1` 模式：Start-OnDesk 起 CAD，python 也在同一桌面上跑，线程里枚举 `#32770` 窗口记文字并点确定）。

改法：

* CAD 里已加载的文件（打开着的文档、装配里的实例、工程图引用的模型）**只写内存，不碰磁盘**，状态栏提示 Ctrl+S；
  内存那份写不进才退回写盘。没加载的文件照旧用属性组件直接写盘。
* 属性组件一律按名字后期绑定（`PropCardCad.Late`，`Type.InvokeMember`，每次现查成员编号）；内存文档一律用 `F.Properties` / `F.Property` 接口类型。**这个文件里不要再对属性对象用 dynamic。**
* 日志记完整异常（以前只记 Message，看不出是 TargetParameterCountException）。

验证（加密副本，`YF25.07G01-L1-M30-02.asm`，104 个文件，勾补齐，写前 64 行）：

| 场景 | 结果 |
| --- | --- |
| 隐藏 CAD，窗口真实路径 | 64/64 写进内存 4.5 s，磁盘 0 改动，日志无错 |
| 接着 `asm.Save()` | 正好这 64 个文件落盘，读回全是新值、缺的属性都补上 |
| 碰过内存文档后，关着的文件补属性（0.8.1 这里全挂） | 3 个文件都写盘成功，26～37 ms |
| 可见 CAD + DisplayAlerts，旧顺序对照 | 弹出和现场一模一样的框（证明监视器抓得到） |
| 可见 CAD + DisplayAlerts，新做法 64 行 | 0 个对话框 |
| 当前文档 = 工程图，写它引用的零件 | 只进内存；`dft.Save()` 把零件一起存盘，读回新值 |

现场数据：用户 18:15–18:17 那次，写盘成功的文件（文件夹里修改时间在这段）已经是新值；退回改内存的那些没保存，要用 0.8.2 重新写一遍。


## 0.8.1（同日）：一打开命令天工就崩

用户原话：「怎么一打开这个功能天工就崩溃了」。

* **根因**：读当前打开着的文档时（加密文件被 CAD 打开就锁住，属性组件读不了，退回读文档的 Properties），
  为了判断下标从 0 还是从 1 开始，`FirstIndex` 去取了 `Item(0)`。文档的属性集合从 1 数，越界**不报 COM 错误**，
  而是 `FWKAUTO.DLL` 访问冲突（0xc0000005），.NET 拦不住，进程直接死（Windows 事件日志 Application Error 1000 + .NET Runtime 1026，栈指向 `PropCardCad.FirstIndex`）。
  0.8.0 的真机测试用的是**未加密**副本：打开着的文件属性组件照样读得了，走不到这条路。
* **改法**：下标起点写死（属性组件 0、文档 1），不再"试一下"；写的时候也先按下标列出已有属性名，不再"按名字取一下看报不报错"。
* 顺带：当前文档是**工程图**时，它引用的模型也在内存里（加密就锁住）→ `LoadedDocument` 加上 `ModelLinks.ModelDocument`。
* **加密文件的规律（真机）**：没打开的加密文件属性组件直接写磁盘；一旦在 CAD 内存里（打开、被装配 / 工程图引用）就 `STG_E_SHAREVIOLATION`，
  只能写内存，要用户在 CAD 里保存。日志 `PropCardWrite 改写内存里的文档 …` 记着原因。
* **测试要用加密副本**（`原件备份_20261023` 里拷），并且用 `Diagnostics.StartPropCardFormTest`（异步，在 CAD 自己的消息循环里跑）：
  同步的 `PropCardFormTest` 是在外部 COM 调用里跑，嵌套调用文档会被消息筛选器拒绝（RPC_E_SERVERCALL_RETRYLATER），是测试假象。
* 验证（全在加密副本上）：当前文档 = 加密零件 / 加密装配（104 个文件，1.0 s）/ 加密工程图，窗口载入 → 填入 → 写入全部成功；
  装好正式版 0.8.1 后用 `StartCommand` 走真实按钮打开加密零件，CAD 不崩、日志无错；激活仍有效。

用户原话：「天工自带的批量写入属性不好用，你能帮我做一下这个功能吗？……新功能用新版本号0.8.0，名字叫属性卡填写。」
「做好了记得帮我安装并激活，算法复杂度最低，耗时最低，功能简单易用哦。」

背景：用户的 SK 模板工程图标题栏引用零件自定义属性（零件名称、设计、项目名称、表面处理、优先等级……），
零件里缺属性就显示「错误：没有参考」；天工自带批量写属性一次只能填一种值、看不到谁缺。

## 二、读写怎么走（真机实测定下来的，别改回去）

* **读写都先用属性组件 `SolidEdge.FileProperties`（PropAuto.dll，进程内）**：不打开文档，一个文件 20～45 ms。
  它在天工进程里，**DLP 加密文件照样能读写**（写完仍是 `%TSD-Header`）；同一个组件在 Python 进程里打不开加密文件。
* ~~**装配里加载着的零件**：属性组件写得进磁盘；写完再把**内存里那份**照写一遍~~ —— **0.8.2 作废**：写盘后再改内存会弹「加载后已被其他用户修改」。现在已加载的文件只写内存，见本文开头。
  内存文档取法：收集时记下「文件 → 第一个实例」，写哪个才取哪个的 `OccurrenceDocument`。
  一次把全部实例的文档都取一遍，105 个零件的装配要 **9 秒**（量过）。
* **当前打开着的文档本身**（正开着的装配）：属性组件打不开（被占用）→ 只写进内存，**不替用户保存**，状态栏提示 Ctrl+S。
  从插件里保存装配会弹对话框把 CAD 卡死（真机卡过一次）。
* 两个 COM 坑：
  * 打开着的文档的属性集合要**按接口类型**（`F.PropertySets` / `F.Properties`）调 `Add`。用 dynamic 调会报 `DISP_E_NOTACOLLECTION`。
  * 属性组件那边按接口类型转换不会报错，一调用就报 `DISP_E_MEMBERNOTFOUND`（成员编号不同）。0.8.1 用 dynamic，结果两边的 dynamic 缓存互相串；0.8.2 改成按名字后期绑定（`PropCardCad.Late`）。
* 集合下标：属性组件从 0 数，文档 Properties 从 1 数（0.8.1 起写死，`FirstIndex` 试探会让天工崩溃）。
* 只写改过的文件：一格没改的文件（标准件、外购件）绝不写，哪怕勾了「补齐」。
