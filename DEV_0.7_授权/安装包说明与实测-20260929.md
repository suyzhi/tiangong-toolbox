## 3. 命令行行为（install.ps1）

```powershell
# 安装（弹窗询问是否强制结束天工进程）
tools\install.ps1 -LibraryPath payload\TianGongCadSuite.dll -StageDirectory "%LOCALAPPDATA%\TianGongCadSuite\app"
# 无人值守（不弹窗，直接强制结束）：上面那条再加 -Force
# 卸载（同样先问）
tools\install.ps1 -Uninstall
```

要点：

* **只结束这几类进程**：`TianGong`（CAD 本体，含转换器拉起的隐藏 /automation 实例）、`TianGongConverter`、`TianGongDrillWorker`、`PanelLauncher`、`TrainingExportRunner` —— 不动别的程序。
* 结束不干净会重试，并把没结束的 PID 报出来，不会静默继续。
* 弹窗里明确写了"未保存的模型 / 图纸修改会丢失"。
* 不碰 `HKCU\Software\NDS\TianGong\...\AddIns` 那条加载项记录（历史教训：删了以后 CAD 只重建却不加载）。

## 5. 下线的两个命令怎么"恢复"（万一以后要用）

命令不是删代码，而是"不注册到功能区"：`src/PluginFramework.cs` 里

```csharp
static readonly int[] Hidden=new int[]{1,4};   // 1=四面生成内嵌板 4=导出出图训练数据
```

把对应 id 从这个数组里拿掉、重新编译即可恢复按钮（命令 ID 永久保留，不会与别的命令冲突）。

## 6.5 复验时又发现并修掉的两个问题（2026-09-29 下午）

1. **升级时"旧 DLL 被占用，复制失败"**（顺序错）
   - 现象：CAD 正开着（插件从 `app\` 目录加载，DLL 被映射）时运行安装 →
     `Copy-Item : The process cannot access the file '...app\TianGongCadSuite.dll' because it is being used by another process.`
   - 原因：安装脚本把"复制 payload"排在"检测/结束天工进程"之前。
   - 修法：改成**先清进程、再复制**，并且复制带 8 次重试（进程退出后文件句柄偶尔还要几百毫秒才释放）。
   - 复验：
     * 顺序：用一个占位进程独占锁住目标 DLL + 用户 CAD 正开着 → 安装脚本**先弹提示框**（"检测到 1 个天工进程…"），
       不再出现复制失败；选「否」正确退出（"已取消。请先保存并关闭天工 CAD…"），什么也没杀、文件没动。
     * 完整路径：用一份进程名单改成占位进程的脚本副本（避免动到正在用的 CAD）+ 占位进程独占锁住目标目录 →
       `正在结束 TianGongLockHolder (PID 19764)` → `天工进程已全部结束，继续。` → `已把插件文件安装到：…` → `注册完成`，
       文件锁在进程消失后立刻可写（重试生效）。

2. **`.cmd` 编码**：安装/卸载 .cmd 里的中文提示原来被写成 UTF-8（PowerShell 7 的 `[Text.Encoding]::Default` 是 UTF-8，
   不是系统 ANSI），在 GBK 控制台里会显示成乱码。已改成显式用**系统 ANSI 代码页**写入；
   另外管理员的 `授权管理.cmd` 改成**纯 ASCII 内容**（文件名仍是中文），任何代码页都不会读错。

## 7. 还需要用户决定的一件事

这台机器上另有**两个更早版本**的同一款插件还在注册表里（`矩形板 (DEV 0.1.2)`、`矩形板 (DEV 0.3.0)`），
它们也在功能区加了按钮（`生成矩形板`、`多型材自动填充`），与新版**同名但不同实现**，容易点错。
建议用 `DEV_0.7_授权\tools\uninstall-old-addins.ps1` 卸掉（默认干跑，加 `-AutoUninstall yes` 真删）。
新安装包本身干净，不含这两个旧加载项。
