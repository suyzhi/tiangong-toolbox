# 2026-10-13（0.7.3）：特征编组命名 · 螺纹深度可调 · 孔跟随参考孔 · 界面重排

## 用户提的五件事

1. 每个孔都是一个单独的特征，特征树里一长串；
2. 特征名（"4.917 简单孔 3"）看不出孔型和孔径；
3. 打出来的孔和参考孔没有关联 —— 参考零件一挪，所有孔全错位；
4. 螺纹孔的螺纹深度只有一点点，而且没法调；
5. 打孔窗口难看、不好用。

## 真机事实（tools/hole-feature-probe，225.03.00.165，私有桌面上新建文档量的）

| 问题 | 实测 | 结论 |
| --- | --- | --- |
| 一个孔特征放多个孔 | 轮廓里 `Holes2d.Add` 4 次，Count 确实到 4；但 `Profile.End` 之后只剩 1 个 —— 换遍 `igProfileClosed / 0 / AllowNested / AllowPointsAsProfiles / NoSelfIntersect` 及组合都一样；不调 `End` 则建孔失败。多个 `Circles2d` 同样被收成 1 个。`Hole.SetProfiles(3, …)` → `igFeatureFailed` | **接口做不到"一个特征多个孔"**。改为：同规格的孔编成一个 **特征组**（`Model.FeatureGroups.AddFeatureGroupsBySet`），特征树里同样是一个可折叠节点 |
| 特征改名 | `Hole.Name = "M6沉孔 Φ6.6 ×4"` 成功，`EdgebarName/DisplayName` 跟着变，**保存重开仍在**；`SystemName` 不变（"6.6 简单孔 1"）。`FeatureGroup.Name` 同样可改 | 孔、组都按规格命名；`SystemName` 用来当稳定 ID |
| 螺纹深度 | 现有配方（`ThreadDepthMethod/ThreadDepth` 留 Missing）回读 **igFinite + 2mm**，线框截图里装饰螺纹只有孔口一小圈 —— 就是用户说的"只有一点点" | 必须显式给。`igThroughAll` = 全长（贯通孔整孔、盲孔攻到孔底，两种截图都确认）；`igFinite + 深度` = 指定深度。建后改 `HoleData.ThreadDepth` 也生效 |
| 处理方式 | 第 11 位显式给 `igTappedHole`：孔型仍是 `igRegularHole`，且公称直径 6、螺距 1 能回读（留 `igNone` 时 CAD 也会换成 `igTappedHole`，但公称直径/螺距回读为 0） | 显式给 |
| 跨零件关联 | 装配里 `Profile.IncludeEdge(另一零件的边)` 不论传装配引用还是零件边对象都 `0x80040224`；`ProjectEdge` → `E_FAIL`；`HasInterpartLinks` 始终 False | **CAD 原生的跨零件关联用不了**，改为自己记关联 + 一键同步 |
| 挪孔心 | 已建好的孔特征：`(Profile)hole.Profile` → `Holes2d.Item(1).SetCenterPoint` → `End(igProfileClosed)` → `Model.Recompute`，孔跟着走、状态 `igFeatureOK` | 同步孔位就靠它。⚠ 用 `End(0)` 建的轮廓再 `SetCenterPoint` 会 `RPC_E_SERVERFAULT`，所以一律 `igProfileClosed` |
| 属性集 | `Hole.AttributeSets.Add("TGAutoHole")` + 字符串属性，保存重开仍在；`FeatureGroup` 上也能挂 | 关联记录存在孔特征上 |

## 做了什么

**① 编组 + 命名**（`src/HoleNaming.cs` 纯逻辑；`AutoHoleWriter.Organize`）
同一张面上同规格的孔：成员叫「M6 螺纹孔（螺纹全长）-1 … -4」，组叫「M6 螺纹孔（螺纹全长） ×4」；
单个孔不建组，直接叫规格短名。短名一眼看出孔型/规格/孔径/深度：
`M6 螺纹孔（螺纹深 12）`、`M6 沉孔 Φ6.6/Φ11 深6.5`、`M6 锥形沉孔 Φ6.6/Φ10 90°`、`通孔 Φ6.6`、`盲孔 Φ6 深10 倒角0.5`。
同一零件第二批同规格孔接着往下编号、组名重名加 " (2)"（不依赖 CAD 对重名的行为）。
编组失败（例如特征不相邻）只记一笔、逐个命名，不影响已打好的孔。

**② 螺纹深度**（`HoleSpec.ThreadFull / ThreadDepth`）
界面「螺纹：◉全长 ○指定深度 [12] mm」，默认全长；指定深度默认 2×公称直径（M6→12、M8→16），
换规格时用户手填过的深度保留。盲孔里指定深度超过孔深 → 视图拒画、编辑区红字、「开始打孔」变灰。
打完自检回读 `ThreadDepthMethod / ThreadDepth`，对不上就在结果框里报。剖面图/3D 图按深度画装饰螺纹。

**③ 跟随参考孔**（`src/HoleLink.cs` 纯逻辑；`src/HoleLinkCad.cs`）
打孔时（默认勾「保持与参考孔关联」）每个孔特征写一条 `TGAutoHole/Link`：
参考零件实例路径 + 文件名、参考孔孔心/轴线（**参考零件局部坐标**）、参考孔所属孔特征的 `SystemName`（有的话）、
打孔零件实例路径、当前孔心（打孔零件局部）。
- 认实例：选择引用给的是"零件局部 → 顶层装配"的矩阵，拿它和每个实例比（嵌套子装配两种矩阵取法都算，哪个对得上记哪个）；
- 同步：重新读两个零件的实例矩阵 → 参考孔轴线与打孔面（孔特征轮廓所在基准面）求交 → 换回打孔零件局部 →
  偏差 > 0.001mm 就 `SetCenterPoint` + `Recompute`，回读状态，失败的就地挪回原位；
- 参考孔是孔特征的，按 `SystemName` 找回特征读它**现在**的孔心 —— 参考孔在零件里被改了位置也跟得上；
  不是孔特征的（拉伸切除、导入件）只能跟"参考零件整体挪动"。
窗口底部「关联孔位」条：打开窗口自动检查，"关联孔 N 个，其中 M 个已和参考孔错位" + 「同步孔位 (M)」。

**④ 界面重排**（`src/AutoHoleForm.cs`；`UiKit` 新增 `Segmented` 分段按钮、`FieldGrid` 表单网格、`Card.AddHeader`、`Ui.Small`）
左列 ①参考孔（两行一组：「Φ6.6 ×4 → M6 螺纹孔（螺纹全长）」+ 灰字来由）②打孔面；
右列 ③孔规格（正在编辑谁 + 参数网格：孔型分段按钮、规格/孔径、深度单选、螺纹深度、沉孔/锥孔、倒角，按孔型整行显隐）+ 孔形状（剖面 | 3D）；
底部 ④预览（每种规格打几个）、按钮行（开始打孔 / 保持关联 / 全部重选 / 关闭）、关联孔位条、状态栏。
原来的「规格来源」大卡片（大半空着）并进规格卡片顶部两行；截断的勾选框文字、被切的预览说明一并解决。

## 补：用天工自带的孔命令打开，大小显示 *（同日）

**原因**：天工的孔命令按「标准 + 子类型 + 大小 + 配合」去孔标准表找一行，找不到、或孔的尺寸与那一行对不上，就显示 *（= 非标孔）。
孔标准表在 `Program\SEFactorySettings.sepref`（带 40 字节头的 zip）里的 `Preferences\Holes\GB Metric.xlsx`；
天工自带的「保存的设置」（`Preferences\Custom.XML`）里的孔一律用 **GB Metric**。原来插件建孔：

| 孔型 | 原来写的 | 天工表里对应的行 |
| --- | --- | --- |
| 通孔 Φ6.6 | ISO Metric，子类型/大小/配合全空 | 常规螺钉间隙 / M6 / 普通 (H13) → Φ6.6 |
| M6 螺纹孔 | ISO Metric，只有大小 M6 | 标准螺纹 / M6 → 内小径 4.917 |
| M6 沉孔 | 全空，且沉孔深 **6.5**（经验值） | 内六角螺钉 / M6 / 普通 (H13) → Φ6.6、沉孔 Φ11 深 **6.8** |
| M6 锥形沉孔 | 全空，且锥孔 **Φ10**（按头径估算） | 机用 / M6 / 普通 (H13) → Φ6.6、埋头 **Φ12.6** 90° |

**修法**：`src/HoleStandard.cs`（纯逻辑）收录 GB Metric 表里插件会用到的行（常规螺钉间隙 M1.6–M30、钻头大小 170 档、
标准螺纹 M3–M20、内六角螺钉沉头 M3–M20、机用埋头 M3–M10）。建孔时 `HoleStandards.Resolve(spec)`：
尺寸**完全等于**表里某一行，就把那一行的 标准/子类型/大小/配合 写进 `AddEx` 第 1–4 位；对不上（用户手填的自定义尺寸）
照旧当非标孔（天工显示 * 是对的）。插件自己的沉孔表、锥沉默认直径改成与天工表一致（M6 沉孔深 6.5→6.8、M8 Φ14.5×8.6→Φ15×9、
锥沉取表值，M12 以上表里没有才按头径估算并注明）。界面编辑区写明「天工标准孔：内六角螺钉 M6 普通 (H13)」或「非标孔（会显示 *）」；
打完自检回读子类型/大小。

**真机证据**：`tools/hole-feature-probe/HoleStdProbe.cs` 在同一块板上建旧/新两组孔，回读与存盘重开都确认四个字段原样保存、
尺寸不被改动（`artifacts/hole-std-probe/HoleStd.par`，特征名「旧-…」「新-…」，可直接用天工孔命令打开对比）；
`LinkSyncE2E` 增加断言：6 个孔都写上了 GB Metric 字段。
⚠ 天工「孔」编辑面板是 XTP 自绘控件，私有桌面上模拟的点击/按键都不能展开「孔规格」那一节，所以"* 消失"这一眼没能自动截图，
需要在真实桌面上打开 HoleStd.par 人工看一眼。

## 已知限制

- "一个孔特征里多个孔"接口做不到（见上表），用特征组代替；
- 关联是插件自己记的，不是 CAD 原生链接：挪动后需要点一下「同步孔位」（打开自动打孔窗口时会自动检查并提示）；
- 打孔零件在装配里有多个实例、且记录的实例路径已失效时，按文件名兜底只认唯一实例，认不出就提示、不乱挪；
- 同步后孔心落到打孔面外 / 撞上别的孔，CAD 建不出孔时就地挪回原位并在结果里说明。

# 2026-10-05/06 新增：点一个带孔的面自动认孔 · 点圆柱面认孔 · 沉孔取「下面的孔径」

## 用户提的三件事

1. 打孔前要一个一个点孔口的圆线条太慢（一个面上几十个孔）；**点一个充满孔的面，把上面的孔自动全认出来，并按孔径归类**（和现有参考孔一样，一类共用一份规格）。
2. **点圆柱面也要能认孔**（孔口的圆线条本来就不好点）。
3. 面上是**沉头孔**时，必须认出**孔口下面那个孔径**，否则下面的孔会配错。

## 怎么用（点法）

| 点哪里 | 结果 |
|---|---|
| 孔口的圆形边线 | 加一个参考孔（老用法）；**沉孔会取下面的孔径** |
| 孔的内壁圆柱面（圆锥面、孔口圆角面也行） | 加一个参考孔 |
| 一个**带孔的面** | 面上的孔全部认出来，按孔径归类加进参考孔；这张面**不当打孔面** |
| 一个没有孔的面 | 当打孔面（老用法） |

"点平面的两种含义"由步骤 ② 下面那个勾控制：**点平面自动认面上的孔（按孔径归类）**。
勾掉就是老行为 —— 点平面＝加打孔面（要在"已经有孔的面"上继续打孔时才需要勾掉）。

## 沉孔识别：孔口直径 ≠ 配做孔径

点圆边和点内壁读出来的都是**孔口**那一圈圆。沉孔/锥沉/倒角孔口的孔口比里面大，
拿孔口去配做会一路错下去：Φ11 的沉孔口会被规格表认成 M10 过孔 → 目标件配出 Φ8.376 的 M10 螺纹孔，
而实际要配的是 Φ6.6 的 M6。

规则（纯逻辑在 [src/HoleScan.cs](src/HoleScan.cs)，真机几何见 [tools/facescan-probe](tools/facescan-probe)）：

> 孔口圆下面**同轴**的整圆里，**最小**的那个才是真正要配做的孔径。

真机上量到的事实（100×100×20 板，天工CAD 225.03.00.165，2026-10-05）：

| 孔型 | 顶面看到的孔口圆 | 同轴的下面的圆 | 认出来的孔径 |
|---|---|---|---|
| 圆柱沉孔 Φ11/Φ6.6 深 6 | Φ11 @z=10 | Φ6.6 @z=4（沉孔底）、Φ6.6 @z=-10（出口） | **Φ6.6** |
| 锥形沉孔 Φ11 90°/Φ5 | Φ11 @z=10 | Φ5 @z=7（锥面与圆柱交界）、Φ5 @z=-10 | **Φ5** |
| 孔口倒角 0.5×45° 的 Φ6.6 | Φ7.6 @z=10 | Φ6.6 @z=9.5、Φ6.6 @z=-10 | **Φ6.6** |
| 平孔 Φ5 | Φ5 @z=10 | 只有同径的出口圆 | Φ5（不变） |
| 螺纹孔 M6（按内小径 Φ4.917 建模） | Φ4.917 @z=10 | 无 | Φ4.917（不变） |

* 同轴判据：轴线夹角 ≤ 约 1.1°、径向偏移 ≤ 0.05mm、半径至少小 0.02mm。
* 归类容差同样是 0.02mm，**不能放宽**：M6 过孔 Φ6.6 与 M8 螺纹内小径 Φ6.647 只差 0.047mm，
  一并组就会把 M6 按 M8 配。
* 同一个孔被认出来两次（例如点沉孔底那个环形面：外圆 Φ11 与内圆 Φ6.6）会去重成一个。

## 凸台不能当孔（真机实测的坑）

一块板上立一根圆凸台时，凸台的**底圆同样长在板面的内环上**（实测：顶面 7 个环里，6 个内环，
其中 1 个就是 Φ20 凸台的底圆）—— 只按"内环 + 整圆"筛，Φ20 凸台会被当成一个孔，
然后在目标件上打一个 Φ20 的孔。

判据是**壁在材料的哪一侧**：孔的壁往材料里凹，凸台的壁往材料外凸。
实现：取孔口那一圈壁面（同轴的圆柱/圆锥/圆环面）的 3D 包围盒中心，
看它落在"孔口所在那张面的外法向"（`IsParamReversed` 修正后的那条老规则）的哪一侧。
实测：沉孔壁 z∈[4,10] 而孔口面朝外 +Z → 偏 -6mm = 孔；凸台壁 z∈[10,15] → +2.5mm = 凸台。

判不出来时（找不到壁面、外法向读不到、壁几乎不偏）**一律按孔处理** ——
宁可多认一个让用户在预览里看见，也不要静默漏掉该打的孔。

# 2026-09-25 修复：螺纹孔为什么会自动带锥面

## 现象

打「螺纹孔」，出来的孔口带一个没设过的锥面（沉头锥座），孔也不是螺纹孔该有的样子。

## 根因（真机探针实测，不是猜的）

插件原来造螺纹孔走的是：

```csharp
part.HoleDataCollection.AddEx(igTappedHole, "ISO Metric", Type.Missing, "M6", Type.Missing, /* 其余 32 个参数全 Missing */);
```

在真机上回读这条调用产出的 `HoleData`，得到的是：

```
HoleType      = igCounterdrillHole      ← 传进去的是 igTappedHole，被换成了「沉头孔」
HoleDiameter  = 6.4mm                   ← 不是 M6 内径，是通孔尺寸
Counterbore   = Φ13.71 × 0.8            ← 没设过
Countersink   = Φ13.71 / 90°            ← 这个 90° 锥座就是用户看到的锥面
TGHoleDepth   = 50.8mm                  ← 2 英寸，典型「上次用过的值」
```

实体面构成证实了这一点：`cones=1, CONE angle=45deg, r=6.855mm`，
切除体积 1994 mm³（= Φ6.35 通孔 633 + Φ12.7 沉头环 1206 + 锥座约 110）。

**结论**：天工CAD 内核里螺纹孔不是一个独立孔型。凡是留 `Missing` 的参数，
CAD 会把「上次用过的孔参数」灌进来；`igTappedHole` 在这种输入下会被解析成
`igCounterdrillHole`，并且带上保存下来的沉头锥面。跟用户设不设置无关。

试过但**无效**的写法（4 种组合都实测过）：

| 尝试 | 结果 |
|---|---|
| `SubType = "标准螺纹"` + `Fit = "普通"` | 仍然是 igCounterdrillHole + 锥面 |
| `IgnoreSavedDefaultValues = true` | 仍然被灌入沉头（只对显式传值的参数有效） |
| `Add(igTappedHole, …)` 显式传直径 | 仍然被换成 igCounterdrillHole |
| 建完再改 `HoleType = igTappedHole` | 特征创建直接 `igFeatureFailed` |

## 修法

螺纹孔 = **普通孔 + 螺纹数据**：孔按螺纹内小径建模，螺纹以装饰螺纹显示
（这和 CAD 自己的孔命令一致，内径数据取自 CAD 自带的 `ISOHOLES.TXT`）。

```csharp
// 全部参数显式给出 + IgnoreSavedDefaultValues = true，一个 Missing 都不留
var d = part.HoleDataCollection.AddEx(igRegularHole, "ISO Metric", Missing, "M6", Missing,
    4.917mm /*孔径=螺纹内径*/, 0, 0, 0, 0 /*沉孔/锥孔显式 0*/,
    0 /*孔底角度*/, igNone /*处理方式*/, …,
    4.917mm /*螺纹内径*/, …, 6mm /*螺纹公称*/, "M6" /*螺纹规格*/, true /*忽略保存值*/);
```

同时补上了一条**打孔后自检**：打完孔回读特征的 `HoleType` 与螺纹描述，
一旦 CAD 偷偷换了孔型，就在结果对话框里点名，而不是静默交付一个错的孔。

## 修复前后实测对照

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 实体上的锥面数（贯通螺纹孔） | 1（90° 沉头锥座） | **0** |
| 切除体积 | 1994 mm³（Φ6.35 + Φ12.7 沉头 + 锥座） | **379.8 mm³ = Φ4.917 圆柱，精确相等** |
| 回读孔型 | igCounterdrillHole | **igRegularHole + 螺纹 M6** |

| 孔口倒角 | 不可控 | 勾选后才多出 1 个锥面（0.5×45°） |

## 可视化验收里又抓出来的三个真 bug（同日修复）

把三个命令放到真机上一步步跑（`tools/VisualAcceptance.cs`，跑在私有桌面里），又暴露出三个问题：

### 1. 同一张面打第二批孔会失败

现象：打完一批孔，再点同一个面接着打，报「无法在所选面上建立打孔基准面」。

查法（`tools/PlaneReuseSpike.cs` 实测）：

```
A) 第一次 AddParallelByDistance(face,0) → 成功，RefPlanes.Count 3→4，
   但是 foreach (RefPlane rp in part.RefPlanes) **枚举不到它**
B) 复用同一个基准面对象打第二批孔 → 成功
E) 用「与目标面平行的已有基准面 + 偏移」新建 → 成功
```

所以原来的「遍历已有基准面找共面来复用」永远找不到自己建的基准面，每次都走新建；
而同一张面新建第二次会被 CAD 拒绝 —— 死结。

修法（`AutoHoleWriter.FindOrCreatePlane`）：

1. 枚举改用 `Count` + `Item(i)`（`foreach` 看不到新建的基准面）
2. 加一层**进程内缓存**（零件 + 平面 → 基准面对象），同一张面第二次直接复用
3. 新建时优先走「与目标面平行的已有基准面 + 偏移」，这条路不碰面片对象，
   **即使缓存的面已经失效也能建**
4. 建完**校验法向**：下表面（相对默认基准面是负偏移）用 `igNormalSide` 建出来方向是反的，
   打孔会失败；方向不对就换 `igReverseNormalSide` 再建

### 2. CAD 忙的时候会报假的「打孔失败」

现象：打第一个孔时报 `CO_E_OBJNOTCONNECTED` / `RPC_E_CALL_REJECTED`，直接算失败。
这类是**瞬态**的 —— CAD 正在忙，等一下重试就好。

修法：`AutoHoleWriter.Attempt(...)` 统一包住建基准面、建轮廓、轮廓坐标、闭合检查、
打孔这几处 COM 调用，遇到瞬态 HRESULT（`0x80010001` / `0x800401FD` / `0x800401FB` /
`0x8001010A` / `0x80010108`）就 `DoIdle` + 等 450ms 重试，最多 6 次。

### 3. 刚加载的零件第一个写操作会被拒

现象：装配里刚插入的实例，第一次对它的模型写操作报 `CO_E_OBJNOTREG`。
修法：`Drill` 入口先 `Application.DoIdle()` 泵一次消息循环。

- `VisualAcceptance.exe` 16 条断言全过，含「贯通螺纹孔锥面数 0→0」「切除体积 379.8mm³」

# 命令 6：自动打孔

## 怎么用（三步）

1. **点已有的孔** —— 在任意零件上点孔口的圆形边线。**可以连点好几个，大小可以不一样。**
2. **点要打孔的面** —— 可以连点好几个面，自动累加
3. **点「开始打孔」**

就这样。孔型和规格是自动算出来的，用户不用管。

**没有模式切换**：点圆边就是加参考孔，点平面就是加打孔面。选择过滤器同时开放边和面，点什么就是什么。

界面会实时显示它推出来的映射关系，例如：

> ③ 将打 3 个孔：
> 　　Φ8.5 → 圆柱沉孔 Φ11　沉孔Φ18 深11　(M10)　贯通　×1
> 　　Φ13.5 → 螺纹孔 Φ10.2　(M12)　贯通　×2

### 孔参数可以手动调（不必接受自动推断）

窗口下半部分是**孔参数编辑区**，按参考孔的直径分组编辑：

| 字段 | 说明 |
|---|---|
| **孔型** | 通孔 / 螺纹孔 / 圆柱沉孔 / 锥形沉孔 |
| **规格** | M3–M20（或"自定义"）—— 改规格会自动重填下面的默认尺寸 |
| **孔径** | 主孔直径（毫米） |
| **深度** | 勾「贯通」= 打通；不勾则填具体深度（走 `Holes.AddFinite` 打盲孔） |
| **沉孔Φ / 沉孔深** | 只在圆柱沉孔时出现 |
| **锥孔Φ / 锥角°** | 只在锥形沉孔时出现 |
| **螺纹深** | 只在螺纹孔时出现；填 0 = 跟孔深一致 |

改动同步到该直径组的**所有**孔。列表里每行显示该组当前的完整规格。**不动任何字段就用自动推断的结果。**

### 选择深度：只选最前面那层

`StartPicking` 里设置 `((ISEMouseEx2)mouse).LocateFrontToBack = true`。

不加这一句会出现"透过当前视图里的模型选到后面零件的边线"。`InterDocumentLocate = true`（跨零件选择）仍然保留，两者配合才能既跨零件、又按前后遮挡优先。

### 多参考孔 × 多打孔面

N 个参考孔 × M 个打孔面 → 最多 N×M 个孔，**每个孔只有投影落在那个面内时才打**。
落在面外的会被**跳过**并在结果里写明"跳过 N 个（投影不落在所选面上）"，不会硬打一个跑到材料外面的孔。

## 它怎么知道要打什么孔

核心是**配做反推**（这个规则来自对嘉立创 ICAN 工具箱的实际使用观察）：

| 你点的参考孔 | 它给目标件打 |
|---|---|
| **螺纹底孔**（如 Φ8.5 = M10 底孔） | **圆柱沉孔**（目标件要过螺钉头） |
| **过孔**（如 Φ13.5 = M12 过孔） | **螺纹孔**（目标件要攻丝） |

直径 → 规格 靠查表，容差 ±0.35mm。表在 `src/AutoHoleData.cs` 的 `HoleMatcher.Table`，9 个常用公制规格（M3–M20），数据取自 GB/T 196 底孔与 GB/T 70.1 内六角圆柱头螺钉沉孔。

命中不了标准表时，不猜——按同直径打通孔，并在状态栏写明"未匹配到标准规格"。

界面上「高级」默认收起。只有想手工改孔型/规格/直径时才展开。**正常使用完全不需要碰它。**

## 界面行为上为"无脑"做的几件事

- **不用切模式**：选孔阶段只允许点圆边，选完自动切成只允许点平面。用户不需要知道"现在处于什么选择状态"。
- **顺序容错**：参考孔没选时点面，会明确提示"请先点一个孔"，不会静默失败。
- **重复面去重**：同一个面点两次会提示"这个面已经选过了"。
- **高亮反馈**：选中的面和参考孔会高亮成深天蓝，看得见选了什么。
- **Esc 关闭**，右键也关闭。
- **失败原因直接写在结果对话框里**，不是一句"失败"。

## 底层 API 路径（已实测）

全部结论来自 `tools/HoleSpike.cs` 的 6 轮 spike，在真实天工CAD 2025（225.03.00.165）上跑出来的，不是查文档猜的。

### 可用的路径

```csharp
// 1) 在用户点选的面上建基准面 —— 面可以直接当父平面
var plane = part.RefPlanes.AddParallelByDistance(face, 0.0,
                P.ReferenceElementConstants.igNormalSide, M, M, M, M);

// 2) 建孔轮廓（一个轮廓只放一个孔心）
var profile = part.ProfileSets.Add().Profiles.Add(plane);
double x2, y2;
profile.Convert3DCoordinate(localX, localY, localZ, out x2, out y2);
profile.Holes2d.Add(x2, y2);                       // 孔轮廓元素
if (profile.End(P.ProfileValidationType.igProfileClosed) != 0) throw ...;

// 3) 造孔数据
var data = part.HoleDataCollection.Add(igRegularHole, diaInMetres, Missing x19);

// 4) 打孔（方向要指向材料内部，见下）
var hole = model.Holes.AddThroughAll(profile, side, data);
object desc; var st = hole.GetStatusEx(out desc);
```

### 七条硬约束（踩过的坑）

1. **孔轮廓用 `Profile.Holes2d.Add(x, y)`**。`Circles2d.AddByCenterRadius` 也能通过检查并打出孔（实测确认），但缺少"孔"语义，官方示例用的是 Holes2d，不要赌。
2. **`ProfilePlaneSide` 必须指向材料内部**，指反了 `AddThroughAll` 返回 `igFeatureFailed`。面片的几何法向和实体外法向**不一定一致**（`Face.IsParamReversed` 会反），所以不要算法向——**先试 `igLeft`，失败删掉再试 `igRight`**。实测在反转面（IsParamReversed=True）上一次就成功。
3. **一个轮廓里放多个 `Holes2d` 只会切出第一个孔。** 实测：放 4 个，`Holes2d.Count=4`、`Profile.End=0`、状态 `igFeatureOK`，但切除体积**正好是 1/4**。所以**每个孔一个轮廓、一个特征**。实测 4 个孔 4 个特征，体积比 1.0000。
4. **`AddSync` 在天工CAD 里不可用**，返回 `E_NOTSUPPORTED (0x80004021)`。不要用。
5. **`Profiles.Add(face)` 和 `Sketches.AddByPlanarFace(face)` 都不可用**（`E_NOINTERFACE` / `E_NOTSUPPORTED`）。唯一可行的面定位方式就是第 1 步的 `AddParallelByDistance(face, 0, ...)`。
6. **`RefPlanes.AddBy3Points` 全部参数组合都类型不匹配**（`DISP_E_TYPEMISMATCH`），三种变体都试过。不要走这条路。
7. **打孔基准面必须"位置对 + 朝向对"，两个都要自己验**（2026-10-05 补，用户托盘铝板踩的）：
   - **位置**：必须落在所选面那张平面上。用"平行基准面 + 偏移"建面时，两个方向建出来的面
     **法向可能完全一样**（实测都是 (0,-1,0)），只比法向必然选中先试的那张 ——
     用户零件上那张偏了 40mm（镜像到材料外面）。后果：**贯通孔照样成功、盲孔必失败**
     （盲孔整段切在空气里，CAD 抛 RPC_E_DISCONNECTED），报错文案还会误导成"这个位置已经有孔了"。
   - **朝向**：法向必须**背对材料**。面片参数反向（`Face.IsParamReversed=True`）时，
     `Face.Geometry.GetPlaneData` 给的法向是**扎进材料**的方向；照它建面，**贯通和盲孔都建不出来**。
     外法向 = `IsParamReversed ? -几何法向 : 几何法向`（本零件 17 张平面面逐个核对过）。
   - **最稳的建法**：`AddParallelByDistance(面片, 0, igNormalSide, M, M, M, M)` —— 位置精确 0mm，
     法向由 CAD 按面片朝向给（实测 igNormalSide/igReverseNormalSide/FlipNormal 四种组合结果一致，都朝外）。
   - `AddParallelByDistance` 的第 7 个参数 `FlipNormal` 对"平行面 + 偏移"建法**实测无效**，别指望它纠朝向。
   - 复现与修复报告：`盲孔报错-根因与修复-20261005.md`；探针：`tools/blind-probe/`。

### 其他容易踩的

- **单位是米。** 表里的毫米在 `AutoHoleWriter.MmToM` 处换算。官方示例 `HoleDiameter:=0.01` 就是 10mm。
- **`Hole.Status` 是带参数的 COM 属性**，C# 里不能直接读，要用 `hole.GetStatusEx(out desc)`。`igFeatureOK = 1216476310`，**不是 0**。
- **`Body.Faces` / `Body.Edges` 是索引属性**，必须传 `FeatureTopologyQueryTypeConstants.igQueryAll`，即 `body.get_Faces(igQueryAll)`。
- **`Circle.GetCircleData` 的第三个参数是 `out`**（半径），不是 `ref`。
- **标准孔走 `HoleDataCollection.AddEx(HoleType, "ISO Metric", Missing, "M6", ...)`** 可以成功；标准库不可用时自动降级为同底孔直径的普通孔，并在结果里如实写明"标准库不可用，已按底孔直径建模"。

# 命令 7：批量排孔

## 怎么用

1. 点要打孔的面 —— **方向自动取该面最长的直边**，孔心横向居中
2. 选排布方式：
   - **沿边等分**：给孔数 + 边距
   - **沿边定距**：给间距 + 边距（预览会算出一共几个）
   - **圆周均布**：第 ② 步改成点一条**圆形边线**定位圆心和半径，再给孔数
3. 选孔型（通孔/螺纹孔/圆柱沉孔/锥形沉孔）和规格（M3–M20）
4. 勾「腰孔」可排长圆孔（只对沿线模式有效）
5. 点「开始打孔」

预览行实时显示：`沿 200mm 等分排 4 孔，边距 10mm`。

## 实现要点

- **排孔位置是纯数学**（`HolePatternSolver`），无 CAD 依赖，可单测。
- **面坐标系的 Origin 放在"方向起点 + 面宽正中"**，不是面的角点。放角点会让所有孔压在面的边线上、一半在材料外面（实测 E_FAIL）。
- **圆周模式的面内基向量用 `FaceFrame.Perp`**（= 面法向 × 方向），保证孔落在面内。

# 命令 8：配孔检查

## 怎么用

打开装配 → 点「开始检查」→ 看列表。点一条，对应的孔高亮成橙红。

判定口径：

| 项 | 口径 |
|---|---|
| 连接孔 | 直径 **3–25mm** |
| 同轴 | 方向差 **< 2°** 且横向偏移 **< 0.2mm** |
| 配做合法 | 两孔能匹配到**同一螺纹规格**；都匹配不上标准表时直径差 ≤1mm 放过 |
| 漏打孔 | 某零件上的孔，**射线沿轴线穿过了另一个零件的材料**，但那个零件在这个位置没有孔 |
| 孤孔 | 只有一个零件有孔且轴线没穿过别的零件。**默认不报**（真实装配里太多），去掉"忽略孤孔"的勾才报 |

## 实现要点

- **`Run` 必须拿到"装配里所有零件的名字"**（`allParts`）。只遍历"有孔的零件"永远发现不了漏孔——漏的那个零件本来就没孔。这是实现时踩过的坑。
- **通孔有上下两条圆边，采集时必须去重**（同零件 + 同轴线 + 同直径算一个孔）。不去重会把一个通孔当成两个，还会把同一个孔的两条边配成一对。
- 射线用 `Body.get_FacesByRay`，沿轴线双向各打一条，命中面即认为穿过了该零件。

# 2026-09-26 修复（第二轮：一类根因的漏网之鱼 + 三处交互/性能问题）

## 一、根因只修了一半：沉孔/锥形沉孔/通孔也留了 Missing（高优先级）

上一轮把「螺纹孔自动带锥面」的根因定位成"留 Missing 的参数会被 CAD 灌入上次用过的孔参数"，
但修复只落在螺纹孔的 `AddEx` 正常路径上：**圆柱沉孔、锥形沉孔、通孔、以及螺纹孔的降级分支
都还在用留 Missing 的 `Add()`**。按同一套实测结论，这些孔同样有被污染的余地，而且不一定
改孔型（改成尺寸不对的沉孔，用户根本看不出来）。

修法：`BuildHoleData` 里四种孔型全部走「全参数显式」的 `AddEx`，几何相关的参数一个不留
Missing（不需要的显式写 0：沉孔/锥孔直径、锥角、孔底角度）。

### 「全显式」不是随便给：三个参数给了就炸（`tools/HoleDefaultProbe.cs` 逐项二分）

探针以「已知可用的最小配方」为基线，逐项把某个参数改成显式值，看哪一项会让 `AddEx` 直接
`E_INVALIDARG (0x80070057)`。真机（225.03.00.165）结果：

| 参数 | 显式给值 | 留 Missing |
|---|---|---|
| `TaperMethod` / `Taper` | **E_INVALIDARG** | CAD 灌入 `igTaperByRatio` / 0.05（对非锥孔无几何影响） |
| `TaperDimType` | **E_INVALIDARG** | 灌入 `igTaperDimAtBottom`（同上） |
| `VBottomDimType = 0` | **E_INVALIDARG** | 灌入 `igVBottomDimToFlat`；显式给 145/146 也正常 |
| `Standard = "ISO Metric"` 或 `""`（非螺纹孔） | 正常 | 也正常（两种都可用） |
| `ThreadDiameterOption` / `ThreadTapDrillDiameter` / `ThreadDepthMethod` = 0 | 正常 | 正常 |
| 9 个倒角参数 = 0 | 正常 | 正常 |

所以「全显式」的正确边界是：**所有影响几何的参数显式给值，锥度那三项留 Missing**
（它们只在孔型是锥孔时才起作用，非锥孔下是死参数）。

### 圆柱沉孔的 `CounterboreProfileLocationType` 必须显式给对

剖面位置决定沉孔从孔的哪一端开始切。实测在同一块板、同一个面上：

| 取值 | 切除体积 | 现象 |
|---|---|---|
| `igCounterboreProfileIsAtTop`（149） | 2544.69 mm³ = Φ18×11 + Φ11×9 | 沉孔在表面，正确 |
| `igCounterboreProfileIsAtBottom`（150） | 950.33 mm³ = Φ11 通孔 | 沉孔被切到材料内部，表面上看不到沉孔 |

所以显式给 `igCounterboreProfileIsAtTop`（= 用户点的那张面那一侧）。

### 四种孔型 × 上表面全过（真机）

```
cb-top  Counterbore  OK  type=igCounterboreHole dia=11 cbd=18 cbdep=11 csd=18 cones=0
cs-top  Countersink  OK  type=igCountersinkHole dia=11 csd=20 csa=90    cones=1(45 度锥座)
rg-top  Through      OK  type=igRegularHole    dia=11                  cones=0
tp-top  Tapped       OK  type=igRegularHole    dia=6  threadDesc=M6    cones=0
```

（下表面那组在这个探针夹具里失败，原因是夹具本身：模板的 `igSymmetric` 拉伸没有把板居中，
板体其实在 z∈[0,10]，所以偏移 −5mm 的基准面根本不在材料里。命令 6 用的是"用户点的那张面"，
不受这个夹具问题影响；四种孔型的真实使用路径由 `PanelTests.exe --autohole-fixes` 端到端覆盖。）

## 二、`Audit()` 从"只比孔型"扩成"比具体数值"

原来只比 `HoleType` + 螺纹描述是否为空，所以"沉孔还是沉孔、但尺寸被灌成别的值"这种污染
是静默的。现在回读并比对：孔径、沉孔直径/深度、锥孔直径/锥角、孔底角度（只在显式要了
V 型底时）、螺纹规格。

两个刻意的设计：

- **只比"这条孔自己的特征值"**。回读出来的 `CounterboreDiameter` / `CountersinkDiameter`
  这类"本孔型用不到"的字段，CAD 会顺手填同义值（实测沉孔的回读里 `csd` 会等于 `cbd`），
  那不是几何问题，按它报警只能制造噪音。
- **读不到（COM 抛异常）时返回 NaN 并跳过该项**，绝不报一个假的"回读 0"。

## 三、配孔检查对沉孔的假阳性（高优先级）

`HoleCheck.Run` 原来是"每个零件取该组里**最大**的直径"。圆柱沉孔在实体上有两条不同直径的
圆边（Φ11 过孔 + Φ18 沉孔外径），`SameHoleLine` 只去重"直径几乎相同"的边，所以两条都会留下。
拿 Φ18 去比对方零件的螺纹底孔 Φ8.5 → 必然配不上 → 对一个打得完全正确的"沉孔 + 螺纹孔"
组合报"配错孔"。**命令 6 打的沉孔会被命令 8 判成错的。**

修法：取该零件该组里**最小**的直径 —— 真正与螺钉杆配合、决定螺纹规格的就是过孔那个较小
直径。回归断言（纯逻辑 + 原生各一条）：

- `沉孔 Φ11/Φ18 + 螺纹底孔 Φ8.5 不算配错孔`
- `拿沉孔外径 Φ18 比 Φ8.5 会判配不上`（反向确认这条断言测的是真问题）

### 顺带挖出的两个同轴判定 bug（原生测试逼出来的）

给「沉孔 + 配做孔」加原生回归时，采集结果暴露出 `HoleCheck` 的两个问题：

1. **同一零件的沉孔被拆成两条假轴线**。采集顺序让「沉孔那一条」先入组，而 `GroupByAxis`
   只拿 `g[0]` 做比较，于是过孔那一条因为「跟 g[0] 横向差 40mm」（其实是同一条轴线的另一个
   截面）被分到第二组 —— 沉孔 + 过孔配不成对，配孔检查的假阳性从这里又绕回来了。
   修法：跟组内**每一个**成员比，不是只比 `g[0]`。
2. **反平行的轴线被当成两条轴线**。圆柱边的轴线取自几何法向，同一个物理孔在装配里读出来
   可能是 `(0,0,-1)`、也可能是 `(0,0,1)`（实测同一块板的沉孔与过孔正是这两个方向）。
   原来的 `|dot|` 比较本身是对的，但**分桶键没做符号规范化**：`(0,0,-1)` 与 `(0,0,1)` 落在
   不同的桶里，反平行的候选连比较的机会都没有。修法：`DirKey` 先让第一个非零分量为正。

两条都补了纯逻辑断言（`沉孔的 Φ11/Φ5.5 两条边算同一条轴线`、`轴线方向相反的同一个孔算同一条轴线`）。

## 四、`ContainsPoint` 对圆/圆弧边界的面失真 + 每次都重算

两个问题一起改（`FaceFrameReader.Bounds`）：

1. **圆弧采样**：整圆的 `GetEndPoints` 会退化成一个点，只采样直线端点算出来的包围盒比实际
   面小一圈，落在圆弧鼓出部分的孔心被误判成"投影在面外"而静默跳过。现在把圆的圆心和半径
   显式补进来（圆上任意点 = c + r·(cosθ·u + sinθ·v)，在 u/v 两个方向的极值就是 ±r，
   补 4 个方向点即可精确包住整圆）。
2. **缓存**：算包围盒要走一遍面的边（COM），而实时预览每改一次数字就要判 N×M 个孔心。
   现在按平面数据做键缓存在 `TargetFace.Bounds` 上，后面只做两次点积。
3. 顺手删掉那行两个分支返回值完全一样的死代码（`var u = (...) ? new V3(1,0,0) : new V3(1,0,0);`）。

## 六、性能：真正会拖慢的那一处（漏打孔判定）

`HoleCheck.Run` 判漏打孔时对每个"孤孔"都要拿装配里每一个零件名去试，而
`RayPassesThrough` 拿到名字之后**又重新遍历一遍 `assembly.Occurrences` 找那个零件** ——
每次 `occ.Name` 都是一次跨进程 COM 调用，合起来是 **O(孤孔数 × 零件数²)** 次 COM 调用。
200 个零件、300 个待判孤孔就是千万次量级的属性读取。

修法：`AutoHoleWriter.OccurrenceBodies` 扫描前一次性建好「零件名 → 实体」表，
`HoleCheck.Run` 多一个 `bodies` 参数按名字 O(1) 查表；`rayHitsPart` 委托保留给测试用。

同时把另外三处二次增长也收了：

| 位置 | 原来 | 现在 |
|---|---|---|
| `CollectAssemblyHoles` 去重 | 每读一条圆边就跟已收集的全部记录比（O(E²)） | 先按「零件名 + 直径取整到 0.1mm」分桶，只跟同桶比 |
| `HoleCheck.GroupByAxis` | 每个新孔跟已有每一组比（最坏 O(n²)） | 轴线方向按 ±0.5° 量化成桶键，只在相邻 27 个桶里精确比较 |
| `FaceFrameReader.ContainsPoint` | 每次调用都重新遍历面的边 | 包围盒缓存在 `TargetFace.Bounds` |

## 七、匹配歧义：容差窗口重叠时必须提示

相邻规格的容差窗口是真实重叠的：`M3 过孔 3.4` 与 `M4 底孔 3.3` 只差 0.1；
`M8 过孔 8.4` 与 `M10 底孔 8.5` 只差 0.1；`M6 过孔 6.6` 与 `M8 内小径 6.647` 只差 0.047。
而这些解读要求目标件打的孔**完全不同**（一个攻丝、一个配沉孔），原来谁被选中取决于
表里的遍历顺序，而且完全不提示用户。

修法：`HoleMatcher.Match` 在保留首选的同时记下"另一个说得通的解读"，
两个候选的标准值相差 ≤0.12mm（`AmbiguityBand`）就置 `HoleMatch.Ambiguous`，
状态栏提示"⚠ 这个直径落在容差边缘，请手动确认规格：也可能是 …"。
`Match` 内部改成"首选/次选"结构 —— 注意 `Consider` 里那句 `dev < secondDev` 不能漏，
漏了次选会被最后一个候选顶掉，歧义永远判不出来（这轮实测踩过）。

## 八、PlaneCache 不再永久增长

原来只有打孔中途报"对象已断开"才清缓存，正常关文档没有钩子。现在：

- `AutoHoleWriter.PruneCache(app)`：把"文档已经不在 CAD 里"的条目清掉（缓存键左边就是文档名），
  打孔前最多每 5 秒查一次；
- `PlaneCacheLimit` 兜底：条目超过 256 个整体清一次。

## 九、重试不再看起来像卡死

`Attempt` 的退避从"死等 450ms × 6"改成每 400ms 报一次进度（`AutoHoleWriter.Progress`），
命令 6 把它写进状态栏并 `DoEvents` 一次 —— 用户看到的是"CAD 正忙（建轮廓），正在重试 2/6…"，
而不是一个不动的窗口。总等待时间与原来同一量级。
